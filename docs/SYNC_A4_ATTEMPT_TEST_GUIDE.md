# SYNC-A4 · PC 和 iPad 的坚果云传输测试

这对库只传输合成操作。用分开的物理文件验证后继先到、截断后重试和同一操作 ID 的冲突隔离。探针只读检查因果状态，没有图谱布局写回。两端每轮按发送端同步、接收端同步、接收端核对的顺序执行。

## 两端各准备一次

1. PC 和 iPad 各解压自己的一份 ZIP。用 Obsidian 将 `Knowledge Map A4 Attempt PC` 或 `Knowledge Map A4 Attempt iPad` 打开为新库。保留库名和隐藏的 `.obsidian`，信任这个独立库并启用 **Knowledge Map A4 Attempt Probe**。
2. 在这两个测试库中安装并登录 **Nutstore Sync**。在坚果云创建空目录 `{{REMOTE}}`，两端都选择它。名称框中只填最后一段，不填斜杠。若插件建目录返回 400，先在坚果云侧建好再回来选择。检查该目录与日常库和此前测试目录互不包含。如果日常库同步整个远端根目录，先停在这里。
3. 两端选「双向同步」。关闭实时、启动和定时同步，将 Obsidian 配置目录设为「不同步」，确保 `Knowledge Map Sync/` 下的 JSON 可以同步。若出现同步计划，确认只涉及测试库、没有删除；若出现需要选择覆盖或合并的冲突，先记录实际选项与文件名，保留现场。可参考 [Nutstore Sync 1.6.0 说明](https://github.com/nutstore/obsidian-nutstore-sync/blob/1.6.0/README.md#-按你的方式同步)。
4. 在空远端上先 PC 后 iPad 各手动同步一次。两端分别从命令面板运行「A4 尝试 · 基线 · 检查空目录」。预期均显示第 0 轮符合预期、文件 0。

## 四轮操作

所有「投放」和「核对」均在 Obsidian 命令面板搜索 `A4 尝试`。每轮发送端投放后，先在发送端运行一次 Nutstore Sync，等同步结束，再在接收端运行一次。关闭同步结果面板后，在接收端运行该轮的「核对」。看到符合预期再进入下一轮。

1. **PC → iPad**。PC 运行「1 · 投放后继先到」。同步后，iPad 运行「1 · 核对后继先到」。预期 1 个文件，后继等待 1、就绪 0。
2. **iPad → PC**。iPad 运行「2 · 投放截断正文」。同步后，PC 运行「2 · 核对截断正文」。预期 2 个文件，阻塞 1、等待 1、就绪 0。截断样本故意在一个 UTF-8 字符中间结束。
3. **iPad → PC**。iPad 运行「3 · 投放完整重试」。同步后，PC 运行「3 · 核对完整重试」。预期 3 个文件，已补全截断 1、阻塞 0、就绪 2。完整正文出现在新路径，原截断文件保留。
4. **PC → iPad**。PC 运行「4 · 投放同 ID 不同正文」。同步后，iPad 运行「4 · 核对同 ID 不同正文」。预期 4 个文件，两份同 ID 的完整正文各自保留，隔离 1、等待 1、就绪 0。

## 回传与异常

- 跑完后两端各运行「A4 尝试 · 导出本机报告」。请回传 iPad 的 `SYNC-A4-Attempt-iPad-*.json`，并给出 PC 测试库路径或同时回传 `SYNC-A4-Attempt-PC-*.json`。报告写在各自库的根目录。导出后暂停同步，直接分享报告。
- 若有差异、同步报错或出现坚果云冲突副本，先停在该轮，两端都导出当时报告。请附上轮次、端别和坚果云显示的实际文件名。探针会收录尝试目录内文件的实际路径、字节数、SHA-256 和合成原文的十六进制表示，含未知命名的副本。若副本出现在其他位置，请另附文件本身或它的相对路径与同步明细。保留原文件，无需编辑或改名。
- 若同步完成却未出现预期文件，先保留第一份报告和同步明细。需要重跑同步时只重跑传输和核对，已经写入的样本无需再次投放。

测试用普通写入生成不同物理路径。已有文件检查只用于避免重复点击，精确路径被外部写者抢占时仍可能覆盖。v2 发布门禁保持关闭。
