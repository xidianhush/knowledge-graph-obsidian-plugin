# G5：独立合成库损坏与恢复复验

本轮仅使用新包 `Knowledge Map G5 PC` / `Knowledge Map G5 iPad`。原G4库、日常库和FB2库保持不动。候选仍标0.0.15，不是正式发布。

本包预置一笔**新生成的合成共享布局**，没有设备身份、私有日志或加入凭据。两端各自首次加入；不要点「新建共享布局」。故障样本在包外独立文件夹中，不能整包放入笔记库。

## 一、建立本轮基线

1. 解压PC包到新的目录，用Obsidian作为新库打开，信任并启用候选插件。**必须先打开知识图谱，等图谱显示后，再进入插件同步设置。** 可点左侧知识图谱图标，或运行命令 `Build knowledge graph from current vault`。保留图谱标签页打开；仅有New tab时点「审阅并加入」会因 `graph-unavailable` 等待，不能弹出加入审阅。iPad包也解压为新的独立库并先打开图谱；保留隐藏的 `.obsidian` 文件夹。
2. 为两端配置同一个全新坚果云远程目录：`{{REMOTE}}`。PC本地上传源必须是本轮 **Knowledge Map G5 PC** 库根目录。不要复用G4远程目录；不同同步入口都核对一次实际路径。
3. PC图谱保持打开。在知识地图设置点「查找共享布局」，选择 `{{VAULT}}`，点「选择共享布局」并确认。再点「审阅并加入」，选**采用共享布局**，在窗口底部确认。
4. PC坚果云同步完成→iPad坚果云同步完成；iPad打开图谱，同样查找并选择上述ID，审阅并采用共享布局。不要导入本机布局。
5. 两端图谱应相同：Synthetic两篇笔记、四个标题，无Fifth。导出 `G5-基线-PC.json` / `G5-基线-iPad.json`。本轮不要拖动节点、重置、改笔记或建第二个共享布局。

以下所有文件操作只在PC新库进行。操作目录为：

`{{OPS}}`

故障样本和恢复备份放在**库外**。每次检查前保留图谱打开，等待更新完成。若提示图谱未就绪，等图谱稳定后再点检查；不要据此重建共享布局。出现与下述预期不同的情况，保留当时现场并导出报告，暂不继续下一组。

## 二、未知文件：阻止接收且保留已接受布局

1. 从故障样本 `01-未知文件` 中复制 `unexpected.json` 到上述ops目录。PC同步→iPad同步；两端设置点「检查共享布局」。
2. 应提示共享输入异常，详细原因含 `unknown-file-name`；图谱仍保留基线。两端各导出 `G5-未知-PC.json` / `G5-未知-iPad.json`。
3. 将刚复制的 `unexpected.json` **移回库外的单独备份目录**。PC同步→iPad同步；核对两端ops都已没有该文件，再分别点检查。应恢复正常，基线布局不变。不需要「审阅共享文件恢复」。

## 三、已接受原件缺失：恢复原字节

1. 此时ops里应仅有基线原件，文件名见 `02-原件备份`。将PC ops中的这一个原件移到库外备份目录，不要清空整个Knowledge Map Sync目录。
2. PC同步→iPad同步，两端确认原件缺失后分别检查。应含 `accepted-record-missing`，图谱仍保留基线。各导出 `G5-缺失-PC.json` / `G5-缺失-iPad.json`。
3. 从刚移出的原件或本包 `02-原件备份` 复制**同名、原始字节的文件**回原ops目录。PC同步→iPad同步；检查后应恢复正常、布局不变。不要通过新建共享布局、导入布局或编辑JSON来恢复。

## 四、同ID不同正文：持久隔离及明确恢复

1. 从 `03-同ID不同正文` 复制里面唯一的JSON到ops。它与原件文件名不同，不能覆盖原件。此时ops有两份JSON。
2. PC同步→iPad同步；两端各检查。应显示共享记录异常，原因含 `attempt-conflict-review`，并出现**「审阅共享文件恢复」**按钮。图谱仍保留基线。各导出 `G5-隔离-PC.json` / `G5-隔离-iPad.json`。
3. 将**刚复制的03样本**移到库外备份，保留基线原件。PC同步→iPad同步；确认两端ops仅剩原件。完全退出并重开两端本轮库，打开图谱、设置。隔离仍应保留；移走样本或重开不能自动解除。
4. 两端分别点「审阅共享文件恢复」，先点**取消**。隔离应继续保留，布局不变。然后再次打开同一个审阅，核对预览为原基线，再点底部**确认**。
5. 分别点「检查共享布局」。应恢复正常，无待发布/冲突；图谱与基线一致。各导出 `G5-恢复-PC.json` / `G5-恢复-iPad.json`，各截一张图谱和同步设置。
6. 完全退出并重开两端，先设置后图谱检查，隔离不应复发、ID仍为 `{{VAULT}}`，布局保持。各导出 `G5-最终-PC.json` / `G5-最终-iPad.json`。

请回报：未知/缺失时布局是否保持，移走冲突样本并重开后是否仍隔离，取消是否无变化，确认恢复及最终重开是否正常。文件可一次提交，也可按组提交。

## 本轮边界

Windows独立原生测试已用真实图谱/按钮和受控API注入验证部分写、本机提交失败、写入期间图谱/源变化、冷重开稳定ID及重新审阅。它们不是实际断电或坚果云服务事故；本指南不要求在iPad制造存储故障。PC/iPad+坚果云的上述三组体验仍待用户验收。首次加入前隔离恢复另有宿主/浏览器回归，不要求重复本轮已建立的连接流程。

故障样本只适用于本包ID和原件。新恢复日志不能用于旧候选降级；本轮两端必须使用同包运行文件。G6容量、G7回退/整包、G8发布授权继续保留。
