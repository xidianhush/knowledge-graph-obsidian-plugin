# 架构与修改入口

活动源码是根 src；历史阶段目录和冻结夹具不用于实现新功能。

## 数据流

Obsidian枚举文件 → 按范围筛选 → 读取选中笔记并解析YAML → 确定性建图管线 → payload → GraphCore → renderer/HUD。平台、DOM与宿主API由适配层提供；worker只接收选中输入，没有vault访问能力。

布局编辑 → layout store串行保存 → 未加入时保存本机数据；加入后由统一同步宿主协调私有日志、草稿与共享发布。外部工具传输普通共享文件；接收端完整核验并协调结构后应用。设置/视角/界面留本机。

## 职责与依赖

- pipeline：输入、结构、链接、布局与编码；不读Obsidian、不碰DOM。
- core：payload、布局模型/编辑/持久状态与渲染生命周期；GraphCore注入platform。
- adapters：vault读取、画布平台、HUD、原生预览。渲染器和HUD体积较大；本轮保留交互契约，没有为行数全量拆分。
- sync：因果/正文/布局验证、尝试文件、私有保存、连接生命周期、恢复、宿主。
- easy-sync-setup与宿主内部编排：设备绑定授权和可重入自动准备/选择/加入。obsidian-easy-settings为正式普通区，旧完整设置只在折叠高级区。historical-layout与恢复入口保留已发布的协调/备份/选择逻辑。此前分步引导模块已移至.local，不参与当前构建。
- 正式构建经bundle-sync-host组装同步模块；历史build_sync_a3_probe仅包装同一组装器，保持旧测试入口可用。模块改写器只支持现有命名导入/导出；语法拓展必须先有组装测试。

核心不得反向依赖宿主/DOM；UI不能直接改私有日志或共享文件。新增行为优先放入其领域，而不是继续堆到renderer或统一宿主。

## 同步中的三个不同事实

1. 本机保存成功：数据已进入本机持久状态。
2. 共享目录写入并校验：仅说明本机目录中的字节；不证明上传或对端接收。
3. 对端接受并应用：须由对端自己的校验和实际回执证明。

不得以时间戳选并发赢家，不把收到文件当已接受。pending与草稿保留未完成工作；epoch/指纹使过期预览失效；锁阻止同一事务域并发；关闭时先排空并释放。任何重构都必须保留这些不变量。

## 如何改

提示与按钮：改同步词典、纯引导与呈现，运行状态/DOM/i18n检查。保存与恢复：改对应领域模块，补磁盘失败/重开检查。协议：必须单独设计兼容性，不属于本次1.0加固授权。渲染：先固定几何、交互和资源基线，再做小职责变更。

每次先说明修改会改变哪个可观察行为；纯重构应证明不会改变该行为。文件变短不是验收标准。
