# G4-FB2 两个独立 PC 库同时打开

2026-11-16。只验跨库连接锁；版本仍为0.0.15独立候选，尚未正式发布。使用包内两个**新库**，保留已验收的G4原库和25操作现场。本轮无需iPad、坚果云、远端目录或布局传输。

## 准备

1. 完全退出PC所有Obsidian窗口，尤其是先前的同步候选。旧候选持有全局独占锁，与修复版混开仍会阻塞，这是保留旧版保护的兼容边界。
2. 解压包到一个新的普通目录，得到 `Knowledge Map FB2 PC A` 与 `Knowledge Map FB2 PC B`。分别以库打开，**保留两个窗口同时运行**，使用平时同一个Obsidian程序/配置，不开两个隔离profile。
3. 如提示信任作者，仅对本包合成库启用插件。两个库都进入“Knowledge Map Sync Candidate”设置的“图谱布局同步”。未建图也可以做本轮连接测试。

## 同时操作

1. 在A点「新建共享布局」，应出现连接确认弹窗。先点「取消」，应仍为“当前共享布局：尚未选择”。保持A窗口打开。
2. 在B做同样操作并取消，B也应弹窗，不出现 `connections-registry-busy`。保持B打开。
3. 回A再次「新建共享布局」，点弹窗底部「确认」；再在B同样新建并确认。两个窗口均应显示自己的共享布局ID，**两个ID应不同**。出现需要首次审阅加入的提示是正常的；本轮停在连接选择完成即可，无需导入布局。
4. 两端分别导出同步状态，命名 **FB2-并开-A.json / FB2-并开-B.json**。若点击后未弹窗，先导出当时报告和同步设置截图，不删除配置或重建身份。

## 重开

完全退出这两个窗口，再将两个库同时重开。各自选中的共享布局ID应与退出前相同，A/B仍不同，且无连接忙错误。导出 **FB2-重开-A.json / FB2-重开-B.json**。

回交以上4份JSON，并说明：两库是否都能弹窗、取消后是否未选择、确认及同时重开是否顺利。无需重做已通过的G4标题增删、冲突或两端同步测试。
