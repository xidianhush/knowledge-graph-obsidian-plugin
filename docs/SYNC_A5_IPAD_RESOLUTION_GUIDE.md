# A5 第二轮：iPad 主动解决冲突，PC 接收

继续使用上一轮已完成解决的 `Knowledge Map A6 Resolve PC` / `Knowledge Map A6 Resolve iPad`。沿用两端目前选择的同一个 Resolve 远端目录；本轮不需要新压缩包，不重新解压、不清空目录、不删除旧操作，也不重新初始化。上一轮的报告继续保留。

这次改 **B.Fourth**：PC 向左，iPad 向右，最后由 iPad 选择向右。上一轮 **A.Second 向左** 的解决结果应始终保留。正式 v2 发布门禁继续关闭。

## 1. 确认共同起点

1. 打开上述两个 Resolve 库，确认 A.Second 都保留上一轮向左的布局，B 仍是上一轮未调整的布局。
2. 两端坚果云继续使用双向同步，关闭实时、启动和定时自动同步，`.obsidian` 仍不同步，排除报告 `SYNC-A4-native-*.json` 与 `SYNC-A6-startup-*.json`，允许 `Knowledge Map Sync/`。
3. 按 **PC 同步 → iPad 同步 → PC 再同步**，每次等待完成。两端运行 **「A4 · 检查已到达的布局文件」**，等待完成，确认没有冲突或待发布提示。预期共同起点仍为上一轮的三笔操作。

若起点布局不符，或检查提示异常，先导出两端报告发回，保留现场；暂不进行后续编辑。无需手工修改 JSON 或统计私有日志序号。

## 2. 离线制造 B 的新冲突

1. **两端实际断网**，确认 Wi-Fi/其他网络已关闭。保持断网直至本节两端均已发布完成。
2. PC 进入「调整布局」，将 **B.Fourth 向左拖一段可辨认的距离**，留在 B 的范围内，然后退出布局编辑。不要调整 A。
3. iPad 同样将 **B.Fourth 向右拖**，然后退出布局编辑。不要调整 A。
4. 两端各运行 **「A4 候选 · 发布或重试本机布局草稿」**，等待本机完成提示。此时 PC 应显示 B 向左，iPad 显示 B 向右；A.Second 均保持原位置。本机发布完成不表示云端已收到。
5. 恢复联网，按 **PC 同步 → iPad 同步 → PC 再同步**，每次等完成。两端各运行 A4 检查命令。预期各自继续显示自己的 B 布局，等待解决冲突；A 不变。
6. 两端各运行 **「A4 · 导出本机测试报告」**，注明 **“第二轮冲突-PC / 第二轮冲突-iPad”**。

技术核对预期：共享目录五份操作，各端接受原三笔加本机新一笔；双方新操作应具有相同的上一轮决定作为前驱。用户无需手工检查这些字段。

## 3. 在 iPad 取消一次，然后重开

1. 暂不再同步。**仅在 iPad** 运行 **「A5 候选 · 审阅并解决同组布局冲突」**。窗口应展示 B 的左右两份预览。
2. 初始确认按钮应不可用。点击任意预览后，按钮才可用；这次点击 **「取消选择」**，不要确认。iPad 应仍显示自己 B.Fourth 向右的布局，A.Second 不变。
3. 完全退出 iPad Obsidian，再重开同一 Resolve 库。运行 A4 检查，等完成后导出报告，注明 **“第二轮取消重开-iPad”**。预期冲突仍暂停，布局不变，没有新增解决操作。PC 此阶段不必退出。

## 4. iPad 确认，传给 PC

1. iPad 再运行 A5 审阅命令，点击标为 **「本机已保存」** 的预览，核对是 **B.Fourth 向右**，再点 **「确认并保存决定」**。PC 本轮不运行解决命令。
2. 等待本机完成提示，运行 A4 检查，再导出报告，注明 **“第二轮决定已保存-iPad”**。预期新增第六份操作，之前五份原样保留；B 选择向右，A 保留上一轮向左。此时尚不表示 PC 已收到。
3. 按 **iPad 同步 → PC 同步 → iPad 再同步**，每次等完成。两端各运行 A4 检查。预期 PC 改为 B.Fourth 向右，iPad 保持向右；两端 A.Second 均保留上一轮向左，无未解决冲突。
4. 两端各截图并导出报告，注明 **“第二轮解决后-PC / 第二轮解决后-iPad”**。截图尽量显示 A.Second 和 B.Fourth 的标题与相对位置，可适度放大。
5. 完全退出两端 Obsidian，再重开各自同一测试库，运行 A4 检查并等待完成，然后导出报告，注明 **“第二轮解决重开-PC / 第二轮解决重开-iPad”**。预期两处布局均保留。

## 5. 回传和异常处理

正常共 **八份报告**：冲突双端 2、取消重开 iPad 1、决定已保存 iPad 1、解决后双端 2、解决重开双端 2。保留导出的 `SYNC-A4-native-…json` 文件名即可，回传时注明阶段和平台，以免改名后不匹配报告排除规则。另附解决后双端截图，并反馈 iPad 上预览能否分辨左右、能否顺利点选、取消和确认提示是否清楚。

若出现「共享输入或图谱已变化」、缺少预览、按钮异常、布局不符、同步报错或草稿未完成，暂停后续操作，保留原始文件，导出报告并附提示截图发回。若显示「此前已确认的布局」，说明已有持久保存的决定；关闭窗口会保留它，不表示撤销。不要删除旧文件或在 PC 再确认另一个决定。

核验以实际操作正文、前驱、布局快照和共享文件摘要为准；私有日志序号可以因平台动作不同而不同。私有回执的操作排列也可能不同，不要求两端回执摘要相等，但必须各自可重算、重开稳定，且双方接受相同的操作正文与最终布局。
