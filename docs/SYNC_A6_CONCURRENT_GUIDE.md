# SYNC-A6 离线并发测试

每组使用各自的 PC/iPad ZIP 和新建空远端。先做 Different（不同组），再做 Same（同组）。两组测试库互相独立。本包场景为 **{{SCENARIO}}**，远端为 **{{REMOTE}}**。

## 两组都按此准备

1. 解压对应 ZIP，保留隐藏的 `.obsidian`。在 Obsidian 中打开 `Knowledge Map A6 Different PC/iPad` 或 `Knowledge Map A6 Same PC/iPad`。信任库并启用 Knowledge Map A4 Layout Candidate。库名用于确认场景，请保留。
2. 仅在这些测试库安装并登录 Nutstore Sync，每组两端选择该组自己的新建空远端。包内 START-HERE 有该组实际远端名称。远端与日常库及旧测试目录互不包含。
3. 两端选择双向同步，关闭实时、启动和定时同步，将 `.obsidian` 设为不同步。在两端过滤规则中添加 `SYNC-A4-native-*.json`，让测试报告留在本机。允许 `Synthetic/` 和 `Knowledge Map Sync/` 同步。
4. 先 PC 后 iPad 各手动同步一次。打开图谱，确认 A 下有 First/Second、B 下有 Third/Fourth，布局均为初始状态。之后暂停手动同步，直到两端都完成下面的编辑和发布。
5. 为确保这一段不交换文件，完成基线同步后让两端实际断网。PC 断开 Wi-Fi 或网线，iPad 开启飞行模式并确认 Wi-Fi 关闭。下面的本机布局编辑、发布和导出报告均在断网状态执行；两端都完成“离线发布后”的报告和截图后再恢复网络，继续各组规定的手动同步顺序。恢复联网前再次检查实时、启动和定时同步已关闭。

这里的离线指编辑期间两端不交换共享文件。登录和基线同步在断网前完成，自动同步需一直关闭。

若准备阶段误开了自动同步，先关闭两端自动同步并导出当时报告，保留旧库与远端。只要发布前已经发生过文件交换，该轮就不能用于证明独立并发。重测使用新套件、新解压目录和新空远端，避免旧历史或本机接受记录影响起点。前一步的实际断网用于避免再次误同步。

## 第一组 Different · 改不同组

1. PC 在「调整布局」中把 A.Second 向左拖一段可辨认的距离，点 ✥ 退出编辑。
2. iPad 把 B.Fourth 向右拖一段可辨认的距离，点 ✥ 退出编辑。
3. 两端各在命令面板运行 **「A4 候选 · 发布或重试本机布局草稿」**，等提示「已核验本机共享文件并接受布局」。在两端都完成发布之前，保持手动同步暂停。
4. 两端各截图并运行 **「A4 · 导出本机测试报告」**。这是“发布后、同步前”的证据。此时每端应只有本机那一处改动。请将报告另存或分享时标为 Different-离线-PC / Different-离线-iPad。
5. 按 **PC 同步 → iPad 同步 → PC 再同步** 的顺序执行。每次等坚果云同步结束再继续。两端保持图谱在前台，预期都看到 A.Second 向左、B.Fourth 向右。
6. 两端各截图并导出一次报告，标为 Different-同步后-PC / Different-同步后-iPad。
7. 完全退出两端 Obsidian，再重开这一组库和图谱。预期两处调整仍同时保留。两端各导出报告，标为 Different-重开-PC / Different-重开-iPad。

## 第二组 Same · 改同一组

使用 Same 的全新配对库和新空远端，先做上述准备。

1. PC 把 A.Second 向左拖，iPad 把 A.Second 向右拖。两端各自退出编辑，再运行同一条发布命令。期间保持手动同步暂停，两端应分别看到自己的布局。
2. 两端各截图并导出报告，标为 Same-离线-PC / Same-离线-iPad。
3. 为覆盖另一种到达顺序，这组按 **iPad 同步 → PC 同步 → iPad 再同步** 执行。预期共享目录保留两笔操作，PC 继续显示自己向左的布局，iPad 继续显示自己向右的布局。两端等待处理冲突。
4. 两端各截图并导出报告，标为 Same-同步后-PC / Same-同步后-iPad。当前候选可能只保留原布局而没有专门的冲突弹窗；报告里的 `shared-candidate-blocked` 用于核对暂停原因。
5. 完全退出两端 Obsidian，再重开这一组库和图谱。预期各自布局仍保留，共享应用继续暂停。两端各导出报告，标为 Same-重开-PC / Same-重开-iPad。

Same 测试的两笔操作使用不同操作 ID，属于同组并发冲突。`attemptConflict` 字段可能为 null；它专门记录同操作 ID 不同正文的隔离。请保留共享文件用于核验。

## 回传

每组每端有“离线发布后、同步后、重开后”三份报告，共 12 份。报告实际文件名以 `SYNC-A4-native-` 开头。可以将六份 PC 报告留在对应测试库并提供路径，iPad 的六份报告按阶段分别分享或放进带阶段名称的文件夹再打包。附上每组离线与同步后的截图，说明截图对应哪一组、哪一端和哪个阶段。

若任何一步与预期不同，先停止该组的后续操作，导出两端当时报告并保留文件。若出现坚果云额外副本，记录实际文件名并附文件。若同步后长时间无变化，先导出当时报告，再运行「A4 · 检查已到达的布局文件」，注明是否手动补扫。

本轮验证布局合并与并发暂停。精确物理路径被抢占时仍可能覆盖，正式 v2 发布门禁保持关闭。
