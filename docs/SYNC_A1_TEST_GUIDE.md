# SYNC-A1：Nutstore 双向 JSON 真链路

本测试只验证传输，不是 0.0.16 布局同步候选。仅在新建的独立测试库操作。

## 准备（两端各做一次）

1. 将同一测试包分别解压为 PC 和 iPad 的本地库。在 Obsidian 中打开它；iPad 放在 Obsidian 能打开的本地目录，保持 `.obsidian/plugins/` 隐藏目录完整。两端必须使用同一份包的测试标识；不要重新生成第二份包。
2. 在此测试库信任并启用 **Knowledge Map SYNC-A1 Probe**。命令面板运行「打开双端传输探针」，或点功能区的无线电塔图标；面板中本机角色应分别为 PC / iPad。
3. 两端在社区插件界面安装并启用 **Nutstore Sync**，自行登录。不复制日常库配置，不将密码发到聊天中。
4. 为这个测试创建一个新的、空的坚果云远端目录；两端选同一目录，均选择**双向同步**。不用覆盖云端/还原本地策略，也不用其他同步引擎同时操作此库。
   - 建议在目录选择器中创建 `/Knowledge-Map-SYNC-A1-20261108`，与日常库的远端目录并列；测试/日常目录不能相同，也不能互为父子目录。PC 与 iPad 的测试库均选此测试目录；日常库设置不改。若日常库同步范围为 `/`，则同一根下新建目录仍在其范围内，应先明确隔离方式再运行测试同步。此名称是建议，尚未确认用户实际配置。
5. 本测试无需同步 `.obsidian` 配置。核对普通目录 `Knowledge Map Sync/a1-probe/` 未被排除，JSON 未被过滤，大小限制能容纳小文件。记录两端 Obsidian/Nutstore 版本、系统版本、配置同步开关与是否改过过滤规则；无需提供账号、远端 URL 或凭据。

## 第一轮：前台双向（先只做这一轮）

**计数在哪里、表示什么？** START-HERE 是说明文档。点击无线电塔图标，或从命令面板运行「打开双端传输探针」，才会打开带按钮和计数的面板。`有效 JSON：PC 1 / iPad 0` 表示“当前这台设备已经读到 1 份由 PC 生成的测试文件、0 份由 iPad 生成的测试文件”，不是设备编号或在线状态。`PC 1 / iPad 1` 表示当前设备已读到双方各 1 份。无需自己编辑 JSON；点按钮会自动创建。探针生成文件，Nutstore 负责传输，是两个不同操作。

以下数字以初始两端均为 `PC 0 / iPad 0` 为例。若此前已经点过写入，先记录当前值，后续比较增量；不要删除文件或反复点写入来凑数字。

1. **打开面板**：PC 的本机角色为 PC，iPad 的本机角色为 iPad。检查初始计数。测试期间保持 iPad 的 Obsidian 在前台。
2. **PC 创建一份**：PC 面板只点一次「写入本机 JSON（正常）」。PC 应显示 `PC 1 / iPad 0`；此时只是本机保存成功，还没证明 iPad 收到。
3. **PC 上传**：关闭探针面板（不会删记录），运行 PC 的 Nutstore 同步，等该次同步结束。
4. **iPad 接收**：在 iPad 运行一次 Nutstore 同步，结束后打开探针。先观察是否自动显示 `PC 1 / iPad 0`、最近读取是否为 `event:create/modify`。若没更新，点一次「手动检查文件」并记录点前/点后的结果。如果仍没读到 PC 文件，先反馈，不进入回写步骤。不能据“Nutstore 同步完成”推定 JSON 到达。
5. **iPad 创建回信并上传**：确认 iPad 面板读到 PC 文件后，只点一次「写入本机 JSON（正常）」。iPad 此时应显示 `PC 1 / iPad 1`。关闭面板，再运行 iPad 的 Nutstore 同步并等待结束。这份新文件自动附带“已看到 PC 哪一份文件”的回执，不用手工编辑。
6. **PC 接收回信**：PC 再运行一次 Nutstore 同步，结束后打开探针。预期 PC 也显示 `PC 1 / iPad 1`，PC 的“另一端回执引用本机记录”为 1。若未自动更新，同样记录点前值后手动检查一次。iPad 已有双方文件，因此第一轮结束时两端均为 `PC 1 / iPad 1`。iPad 此时的回执计数可以仍为 0，本轮只要求 PC 收到 iPad 对 PC 首份文件的回执。
7. **记录结果**：两端各点「导出本机报告」。报告在本地测试库根目录，名称 `SYNC-A1-report-PC/iPad-随机ID.json`；其中只有合成哨兵、相关事件、读取原因和插件版本。可通过 Nutstore 传回 PC。向 Codex 反馈两端计数、PC 回执、哪些端需要手动检查、任何无效计数/失败信息；先不进入第二轮。

## 第二轮：离线、重复和恢复

- **离线新增**：在首轮两端均 `PC 1 / iPad 1` 的基础上，断开两端网络（按钮本身不会断网）。PC 只点一次「写入本机 JSON（离线场景）」，本机应为 `PC 2 / iPad 1`；iPad 只点一次同名按钮，本机应为 `PC 1 / iPad 2`。断网期间不运行同步。恢复两端联网后，依次执行 PC 同步→iPad 同步→PC 再同步，每次等结束，最终两端均应为 `PC 2 / iPad 2`、无效 0。先观察自动更新，若需手动检查则记录。此场景验证不同名离线新增均保留，不代表同文件冲突或布局合并通过；恢复后顺序以实际观察为准，不声称控制了真实服务的乱序。
- **重复同步**：两端各再同步两次；计数不再增长、无无效 JSON。探针写入使用唯一文件名，不会通过重复同步生成新哨兵。
- **后台恢复**：在双端均 `PC 2 / iPad 2` 的基础上，保持联网，iPad 回主屏或切到其他 App（不要强制结束 Obsidian）。PC 只点一次「写入本机 JSON（对端后台场景）」，本机应为 `PC 3 / iPad 2`，再运行 PC Nutstore 同步。PC 同步完成后，在 iPad 打开原来的 Obsidian，运行一次 Nutstore 同步，结束后打开探针；预期为 `PC 3 / iPad 2`、无效 0。先观察，必要时手动检查并如实记录。按钮只标记场景，不会控制另一端 App；iOS 后台没有下载不直接算插件故障，本项检验回到前台后能继续接收。
- **关闭重开**：先在两端导出当前报告，保留会在插件重启后清空的内存读取历史；报告后续一起传回。后台恢复完成、双端均 `PC 3 / iPad 2` 后，在 iPad 应用切换器中上划移除 Obsidian，确保不是仅回主屏。此时 PC 只点一次「写入本机 JSON（对端重开场景）」，应为 `PC 4 / iPad 2`，PC 运行 Nutstore 同步直至完成。再打开 iPad 原测试库，先观察已有记录是否仍在，再运行 Nutstore 同步，结束后预期为 `PC 4 / iPad 2`、无效 0；如未更新再手动检查并记录。验证后再由 Codex 给出反向 PC 重开步骤。关闭和重开不使用开发者整页 reload。
- **反向 PC 关闭重开**：在双方均 `PC 4 / iPad 2` 且当前报告已保存后，完全退出 PC 上用于测试的 Obsidian 实例，保持 iPad 打开原测试库。iPad 本机角色确认是 iPad，只点一次「写入本机 JSON（对端重开场景）」，预期为 `PC 4 / iPad 3`，随后在 iPad 运行 Nutstore 同步直至完成。再重新打开 PC 的同一个测试库并运行 Nutstore 同步，结束后探针应为 `PC 4 / iPad 3`、无效 0；先观察自动读取，必要时手动检查并记录。随后两端各导出最新报告，iPad 上传→PC 下载，供最终对比。
- 两端最后导出报告。记录每步是否手动触发同步、是否手动检查；报错只提供探针内容，勿发送含凭据的 Nutstore 配置/日志。

## 技术边界

探针只在含专用测试标记的库启动；只读写固定测试目录、读取专用标记、导出合成报告。同步插件名称/版本/启用状态来自已加载插件清单，不读取其他插件 data.json。不联网，不读笔记正文，不删除文件，不改 Knowledge Map 的运行文件、布局或版本。

目录名与 JSON 格式均为试验用途，A1/A2 结束前不冻结正式协议。JSON 内容精确校验包含中文、Unicode、随机 ID 与对端已观察 ID；这不等于身份认证或完整布局协议测试。事件日志仅保留最近 200 条、扫描最近 100 次、文件最多 512 个，每文件最多 32 KiB；达到上限则停止并报告。
