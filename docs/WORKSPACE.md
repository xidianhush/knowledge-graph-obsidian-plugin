- **已发布记录**：本地引用 `origin/main` 的 `db835e1` 记录0.0.17发布。与一键分支虽然版本数字相同，但源码和资产不同。该已发布参考固定保留，不用于猜测最新远端版本。2026-11-28 G6将当前候选升为1.0.0，禁止覆盖既有Release；实际发布/验证状态见[1.0.0准备记录](RELEASE_PREP_1.0.0.md)。

完整commit由[BASELINE.json](BASELINE.json)固定，不使用漂移的HEAD代替产品决定。它们有共同祖先1c25526，两条功能线互不包含；源码经三方比较整合，不直接以一条覆盖另一条。

## 每次开工

1. 读AGENTS、TODO、README、本文件；确认任务和最新用户决定。
2. 运行 `npm run workspace:check`，核对当前分支/生产入口/必要能力，不能只看文件夹名和版本号。
3. 看 `git status --short`；记录本轮已有修改，不把别人的未提交内容当作可覆盖文件。
4. 若新建工作区，先检查最新相关分支/发布记录和已验收能力，并登记基线后再开发。默认复用当前已隔离工作区，不为每轮聊天再建一份。
5. 新功能不直接在旧分支复制文件后猜进度。需要并行分支时记录来源commit、任务、修改范围与回收方式。

## 结束与交付

执行 `npm run check`，并按风险运行专项。结果记录确切源码/资产摘要、设备和未测项。变更分为保留的一键/恢复能力、独立工程加固、历史证据、拒绝的UI方案；后者保存在私有快照，不参与构建。
