## 先可靠记录意图，再关闭会话

`createLifecycleDevice({device,app,pluginId,locks,...})` 包装原设备接口。独立本地键 `<plugin>:sync-v2:lifecycle` 保存已签名的 disable / switch 请求，包含 installation、随机 token、原/目标逻辑库、起始连接 generation 和 enabled 状态。签名使用原设备 HMAC，正文绑定逻辑库与 `lifecycle/<token>.json`；复制配置、换设备密钥、改 token 或正文均不成为有效意图。

generation 约束每个允许的中间步骤：原库启用→原库禁用→目标启用→目标禁用。进度可以在这些点恢复，但已完成旧意图不能在后来重新启用后再次关闭连接；拒绝不匹配状态并保留槽，不猜测/覆盖新连接。原设备 App 记录版本未改，也不从 data.json 接受意图。

`createSyncLifecycle({device,openBundle,checkpoint})` 接管宿主入口：

- open：先处理未完成的本地意图，不先打开任何私有库或访问共享发布；已有意图无法验证则停止。
- run：只在 ready 时接收正常动作，经单一队列和容量 admission 执行。冻结/禁用/容量暂停时返回 held，不调用新动作。
- disable / switchTo：先冻结新入口，可靠保存意图，再排空此前已接收动作，依次关闭协调器、配置投影、会话和底层连接，最后完成设备状态并清槽。
- enable：明确重新启用后恢复原私有日志，不自动发布 outbox、不取消待处理布局或清空草稿。
- join：新命名空间保持 join-required，必须显式调用已有加入/备份/校验流程；不能由 open 工厂擅自初始化空接受状态。

切换目标最终保持 **disabled**，不自动打开/采用目标历史；原库文件、草稿、outbox 与各库进度锚保留。再次选择原库能恢复原状态。本地意图槽在 source disable / target enable / target disable 全部完成之前持续存在，崩溃后先将目标归于禁用，再清槽，不在重启时悄悄恢复同步。

`openBundle` 只构造资源句柄，并返回单独的 open 方法；控制器拥有打开失败后的清理责任。获取私有租约后配置加载失败，也会排空并关闭句柄，不泄漏租约。意图写失败或“实际写入但确认抛错”会释放原会话；只有确认完成才报告 disabled，重启可读取实际保存的签名槽继续处理。

关闭会排空已接收的明确动作，不凭空执行待发布操作；此前用户已经排队的操作可能完成。收到关闭请求后，新动作不得进入。导出期间也允许立即记录关闭意图，待只读导出结束后关闭，导出完成不会把 closing 状态错改回 ready。

这些是调用层门禁，正式宿主必须把输入/保存/发布都通过该控制器，不能把原 device、raw store 或 bundle 暴露给其他绕过入口的写者。当前工厂中的空库初始化只用于合成夹具，不是实际宿主策略。

## 私有容量检查与保留区

`createPrivateStoreBudget({store,limits})` 包装底层完整创建接口，放在设备签名包装之下，因此清点的是包含 MAC 封装的实际文本正文。默认工程阈值：

- 正常 admission 在 **64 MiB 正文 / 4096 个数据文件 / 3968 个日志事件**任一触顶时暂停。
- 已准入工作与受控恢复可使用保留区，但每次创建前仍检查 **144 MiB / 8192 文件 / 4096 事件**硬限额，越界前拒绝，不安装新文件。
- 保留 80 MiB、4096 个数据文件和 128 个事件的余量，用于完成一个已审核上界的动作及必要恢复；不把任意无限循环回调都视为可完成的合法动作。

run 在动作开始前检查软限额；同一动作已经接收后，不因中途越过软阈值而突然切断，仍受硬限额保护。recover 只用于受控打开/日志恢复等维护流程，不是普通输入的后门。宿主需要一个经过预算审核的动作对应一次 admission，并等待它的全部工作完成，禁止在回调外继续异步写。

现有文件名可返回 exists 并校验，不改写已有正文；达到硬限额也不删除历史来放行。达到软限额时仍可读取、生成兼容数据、导出回查资料和关闭连接。已存在超额但仍可验证的日志，可通过维护入口只读打开；未知/损坏或超原有读取上限的资料仍保持 recovery-required，不声称所有坏目录都能自动修复。

inventory 覆盖未引用 blob 与中断 `.tmp` 正文。Node 测试控制面的 `.leases` 不计入数据预算，保留既有最多 4096 租约检查；文件清点拒绝符号链接，达到扫描上限返回 complete=false 与下界，不能把已处理子集当总量。IndexedDB 按可信前缀清点记录，检查正文大小字段并对数量/字节上限提前停止；不跨设备/逻辑库扫描。

这里限制的是文本正文与记录数，**不是 OS 磁盘页、索引、临时内存或浏览器总配额**。系统自身 quota/IO 错误仍可能出现。硬错误保留所有已存在记录并要求恢复，未准入的编辑必须由正式交互层保留预览/明确暂停，不能对用户谎称已经持久保存。

清点实现目前保守地逐项扫描；大历史下可能成本较高。默认阈值是待规模/移动端验证的工程护栏，不是正式用户容量承诺；尚需近限额的时间/内存测量及必要的事务计数优化。没有自动 GC、历史压缩或静默清空。

## 同库恢复、兼容输出和回查导出

同一设备明确 enable 原连接后，原签名日志恢复接受状态、设置/UI、草稿、待发布正文与历史。测试保留了已暂存但尚未发布的布局操作，关闭/切换/重启均未偷偷上传或取消它。

compatibilityData 是只读输出：有效设置/UI/未知字段，加当前**已接受布局**，可供后续兼容交付使用；未保存草稿和 outbox 不混成已提交布局。它只返回数据，**没有自动写回 data.json**。组合超单份 JSON 限额时拒绝，分片回查导出仍可单独选择。

exportRecovery 要求调用方明确提供预算外、完整不覆盖创建的 destination 与固定随机 id。冻结新输入并排空队列后，按接受快照、草稿、待发布操作/备份/候选、私有配置、初始配置/加入备份和已接受操作分片输出。每片有正文摘要与大小，预检总正文默认不超过 128 MiB，单片 8 MiB，片数最多 1100；写前复核源未变化，每片读回验证，**最后**安装 manifest。失败保留已有片段，未写清单不得报告完成；同一源/id 可幂等续接，同名不同内容绝不覆盖。

包 scope 固定为 `review-only-not-acceptance-ledger`，不读取或主动导出设备本地签名密钥；原插件配置、草稿和备份仍属私有资料。它用于回查/手动恢复材料，**不是完整私有数据库备份，不含全部历史文件，也不是跨设备接受凭据**。清空数据库后一键导入、丢失本机 localStorage 后恢复信任、把旧布局作为新独立根加入，仍需后续明确恢复/导入流程，不能把这个 manifest 直接喂给 initialize 冒认已应用。

关闭后的正式宿主如何继续本地编辑、兼容落盘与恢复入口尚未接入；本轮没有把旧 data.json 自动覆盖成私有配置。当前只能承诺原型的禁用/重启/再启用和只读输出语义，产品体验留 A5/用户验收。
