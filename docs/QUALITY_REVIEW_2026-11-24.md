## 结论与判断尺度

已经超过纯演示原型：项目有正式发布、本机布局持久化、宿主隔离、同步因果与恢复保护、合成回归及多轮用户设备反馈。当前更准确的描述是：**已有真实交付能力，但维护和交付体系尚未跟上功能复杂度的早期产品**。

“开发者觉得一般、普通用户可能不好用”是合理的产品风险判断；普通用户究竟卡在哪里，仍需观察，不能仅由代码审阅或自用感受确定。

本评估以“普通用户可以独立完成核心任务，开发者可以安全修改、验证、发布”为目标。通过不等于没有改进空间；缺少证据标作待核验，不等于已发现缺陷。没有用未经标定的百分制分数制造精确感。

## 1. 软件架构与可维护性

**判断：基础分层通过；复杂模块的可维护性需要改进。推荐渐进加固。**

已有合理分工：`src/pipeline/` 处理建图；`src/core/` 处理布局和图谱核心；`src/adapters/` 对接画布、DOM 与 Obsidian；`src/sync/` 划分协议、历史、私有保存、连接生命周期和宿主。GraphCore 注入 platform，显式处理暂停、销毁、监听和帧调度；vault 读取与 YAML 解码在管线外。这些边界值得保留。

主要风险：

- `src/core/renderer.js` 2060 行/108680 字节，`src/adapters/hud.js` 1170 行/54897 字节。体积本身不证明设计错误，但渲染、交互、提示和编辑行为集中，局部改动需理解较多上下文。
- `src/sync/obsidian-unified-host.mjs` 470 行/48097 字节，聚合加入、保存、接收、导出、轮换、状态等职责；`persistence-prototype.mjs` 894 行/70624 字节。大量单行多动作与闭包状态使事务顺序难读。
- 正式 `scripts/build.mjs` 经 `build_sync_a3_probe.mjs` 生成统一宿主；后者兼顾多种历史候选，使用正则改写 import/export，正式构建仍有 candidate/probe 命名。它目前能构建，但源码语法与构建器规则耦合，增加接手和修改成本。
- 当前有 16 个 `*prototype.mjs` 同步模块；名称已不能直接说明是否正式运行。不能只因叫 prototype 就判为低质量，也不能据此删除。

改进建议：先写短架构说明和依赖方向，再分别抽离 renderer 的输入/视口/绘制职责、HUD 的预览/搜索/布局控制、同步宿主的加入/恢复导出/状态呈现。每次只移动一个职责，以现有契约和针对性回归证明行为不变。正式构建入口与实验入口分开；是否采用成熟打包器先做独立验证，不把工具迁移和功能变更揉进同一批。

完成标准：新贡献者能回答“改某项行为应去哪个模块、不得依赖什么、跑哪些检查”；纯核心不依赖 Obsidian/DOM；正式入口不需要理解历史探针；拆分前后合成契约、必要像素/交互和持久化行为一致。**不以文件行数下降作为唯一指标。**

## 2. 代码规范、简洁与可读性

**判断：有工程意识和测试基础，可读性/自动规范未达持续维护目标。**

GraphCore 的注释、资源回收、稳定错误码、同步验证与合成测试是优点。问题是风格跨度很大：较清晰的多行代码和极密集的同步代码并存；package 没有 lint/format/typecheck 入口，本次检索未发现对应独立配置。JavaScript 本身不是问题，没有必要为了“专业”一次性全量改成 TypeScript。

建议先规定格式与命名，旧文件按修改范围渐进整理；格式化与逻辑变更分开。引入静态检查并控制新告警，不能一次修全仓顺便改行为。优先给同步输入输出、布局 schema、宿主回调和错误状态加 JSDoc/类型；新模块可评估 TS。为序列化、锁、epoch、pending/accepted 等关键状态补充“为何需要”的注释。用明确的结果类型减少散落的字符串状态和重复分类。

完成标准：小改动无需顺带理解多条事务；变更前能说明输入/输出和失败方式；新代码有统一检查，相关回归可定位到行为契约。测试应覆盖外部行为和危险边界，不只断言内部实现细节。

## 3. 数据安全与隐私

**判断：已有重要保护；尚不能给“全面安全通过”的结论，需专项核验。未在本轮证明存在泄露或丢失漏洞。**

已见保护：vault 文件先按范围筛选再读，明确排除 API Key 路径；建图 worker 不直接读库；同步有规范正文/摘要/身份/因果校验、读取预算、损坏阻塞、原件和恢复包保留；恢复导出目录有相对路径限制。源码关键词检索未发现直接的 fetch/requestUrl/XMLHttpRequest/WebSocket 调用，这支持“插件未直接实现网络上传”，但不构成对全部间接行为的证明。

必须继续准确披露：同步文件含相对路径、标题结构和坐标；第三方同步工具可能上传它们；摘要不是作者认证或加密；有目录写权限的参与者属于信任边界；完整备份可能含未知配置字段。README 已说明数据位置和第三方传输，值得保留。参见 [现有正式评审](SYNC_0.0.16_FORMAL_REVIEW.md) 的数据边界；原条件保证不因本评估扩大。

需核验：

1. 导入、共享文件、备份目标和异常路径的输入限制；超大/截断/恶意 JSON、路径逃逸、未来 schema 的行为。
2. HUD 的 innerHTML 及预览链：常量模板和已转义内容可用；来自笔记/载入 payload 的内容必须追溯来源。`note.preview` 的浏览器 fallback 有 HTML 插入，Obsidian 另走原生预览服务；**这是审查点，不是已确认 XSS**。
3. 磁盘写入中断、空间不足、损坏、迁移、私有存储丢失和恢复流程，按当前构建核对已有测试，不机械重做全部历史实验。
4. 对“将进入公开仓库的差异”和实际交付包做秘密/绝对路径/真实笔记标题筛查；检查 `.integration-tmp/` 等未跟踪产物的处置。不能仅依赖 .gitignore。
5. 本地 build 仍可能把 `.local/smoke-payload.json` 复制到 dist；白名单打包能隔离，但整包 dist 存在误交付风险。建议测试产物与正式产物从目录上分开，默认正式构建不带私有快照。

完成标准：数据流/读写范围、信任模型、备份/删除/卸载影响有明确文档；上述边界有可重跑证据；未知和残余风险写清。无需为宣传轻率承诺端到端加密或“绝不会丢数据”。

## 5. 后续如何扩展而不破坏旧功能

**判断：已有很好的共同维护约定和回归起点；日常 CI 与分层验收仍有缺口。无法保证零回归，可以显著降低并及时发现回归。**

本次看到的 `.github/workflows/` 仅有 release.yml：tag/manual 触发，构建、打包、来源证明和资产白名单完善；**没有在该流程中调用 npm test，也没有常规 PR 检查工作流**。这是优先补齐项。无需运行依赖安装的零 npm 运行时依赖结构是优点；未来引入工具依赖时再补 lockfile，不为了规范空加依赖。

建议每项功能遵守以下轻量流程：

1. TODO 记录任务 ID、实际/期望、复现和优先级；新功能明确用户任务与非目标。
2. 写影响范围：读写哪些数据，改变哪些契约，触及哪些平台；高风险方案先评审。
3. 保全工作区，在隔离分支/工作区实现一个可验收小批次。先复现缺陷，补能捕获旧问题的测试；重构与新增功能分开。
4. PR 自动跑构建、合成契约、静态检查、版本/打包/私有文件防漏检查。协议/持久化修改加相关磁盘和中断检查；UI 改动加浏览器及必要原生场景；性能改动固定样本和计时边界。不要把所有真机成本强加到每个文案修改。
5. 独立代码审阅重点看行为和数据风险。同步协议、数据迁移、恢复和持久化不能只靠实现者自证。
6. 技术验证后标“待用户验收”，只请用户体验本次受影响流程；技术可自动化部分由 Codex 承担。用户反馈与技术结论分别记录。
7. 冻结候选字节、核对安装版本、备份/迁移/回退，再交可审阅发布结果。发布用明确源码和同一套经过验证的资产，日常开发通过的检查不能替代实际发布引用的检查。

核心长期回归契约应至少覆盖：笔记不被改写、过滤先于读取、建图确定性、预览/跳转、缩放/拖动/撤销、布局重开与结构协调、写入失败、同步关闭不发布、首次加入必须审阅、乱序/重复/冲突/损坏/容量保护、备份与降级。承诺支持的平台做明确矩阵；未测平台不扩写为支持。

## 1.0.0 的定义与门槛

可以把 1.0.0 定为本轮打磨的目标，但不应承诺“无可挑剔”或与 iPhone 的产品复杂度/资源作直接对标。更有价值的目标是：在明确范围内，让用户放心依赖、让维护者敢于继续修改。

[SemVer](https://semver.org/lang/zh-CN/) 把 1.0.0 作为稳定公共 API 的起点，并非零缺陷证书。对本插件，建议把布局格式/迁移、保存和恢复、同步协议边界、核心操作及支持平台视作需要明确管理的兼容契约。内部代码仍可改进。

建议门槛：

- 发布范围与非目标明确；Android 目前计划 0.0.17，是否成为 1.0 前置条件**待用户决定**，不因当前建议擅自后移或承诺。iPhone 未验证状态继续准确披露。
- 三份空文件与源码/候选归属核清；干净 checkout 的构建、默认回归、必要专项和打包检查通过，公开资产无私有数据。
- 范围内核心流程不存在尚未处置的阻塞；数据安全问题得到修复，或收窄支持范围。已知外部服务限制应有用户能理解的边界和恢复出口。
- 当前正式版到候选升级、保存重开、失败恢复、完整备份和回退有相应设备/构建的证据。历史通过可用于定位需补什么，不能自动替代最终构建证据。
