## 外部接受：只读共享，不再发布

`acceptExternal()` 从选定命名空间完整枚举 JSON、限制数量/原始字节，并处理服务生成的冲突副本。规范文件名与正文 ID 不符、未知协议/外库、部分 JSON、无规范原文件的孤立副本均停止接受。相同正文副本去重，不同正文同 ID 参与 taint，不能按文件名略过冲突。

已接受记录必须仍有对应规范共享文件且正文摘要不变，不能把消失/被替换的历史从 appliedIds 裁掉。曾取消的本机 intent 若再次可见，或其 ID 对应另一个正文，保留待审阅，不把它冒认为全新远端编辑。

候选经过完整因果、事务、身份和当前隔离模型检查。缺前驱、同组冲突或不兼容时保留旧接受状态；有 staged 本机操作时等待，不能改掉其旧基线。当前外部接受器对整个集合采用保守门禁：任一分量阻塞，本轮不推进接受凭据；A2 核心能产生独立分量 preview，但这里尚未把其部分应用集合持久化。不能宣称已有冲突时其余组都能自动接受。

接受前先保存正文/候选 blob，再次扫描比对集合 fingerprint 并检查 epoch。只有稳定候选才写 receive 事件；重启从该事件恢复，不创建新的共享操作。没有新记录且投影相同则 noop，不增长日志或循环写缓存。测试还监视 sharedStore.create，确认接收和重复接收调用次数为零。

接受凭据 fingerprint 是本机完整已接受正文引用和快照的摘要；local-state、pending 等日志变化不改变它。它不是设备签名或云端回执。调用 A2 作者时，下一笔操作可以引用已接受远端的头，而不是从“扫描完成”推定前驱。

## 设置、UI 与布局缓存

协调器只把本机接受日志的快照写入 layoutOverrides；刚同步来的 data.json 中的 layout/appliedIds 不产生接受事实。设置草稿只拥有 settings/pipeline，UI 按 key 修改，其他字段从执行时的新文档保留，不再用打开表单时的整份旧副本回写。

设置草稿保存 base/value，按字段三方合并：用户未改的值使用新文档值，双方同值不冲突，不相关修改合并；同一字段不同改动保留草稿和文档，返回 review-required，不静默择一。数组按完整字段比较，不逐下标拼成意外列表。使用既有设置验证器，不放宽 include/remap/language/debounce 等验证；外部设置本身无效时也不借 UI/缓存保存把它重新写回。

saveUi 先把 key 的原值与新请求可靠写到 local-state，写文档失败时保留待重试的 UI 意图。即使已有失败的设置保存等待，后续 UI 操作也先保留，不能直接返回“等待”却丢掉用户请求；同 key 的外部冲突需要审阅。

布局草稿单独保存目标和**提交该编辑时可见的接受 fingerprint**。接收正在异步进行时，排队的新布局编辑仍标记旧基线，不能待它入队执行才冒认新布局已被用户看到。草稿存在会阻止外部接受；写 UI/缓存不会把它提前变成已接受布局。清理草稿必须匹配其 ID，避免迟到取消清掉另一笔新编辑。

保存过程中继续输入设置，也不能被上一笔保存完成后的清理抹掉：排队输入保留为基于本次已保存值的新草稿；在异步清理窗口到达的输入使用已确认的上一笔保存重新建立基线。新输入最终可靠保存后才完成自己的 Promise；没有完成可靠暂存的输入，不被宣称已经具备进程恢复保障。这里尚无真实 UI 绑定，保存中/冲突/继续输入的体验留后续接入和 A5。

## 条件写与中断恢复

协调器依赖 `documentStore.read() -> {version,data}`、`compareAndSet(version,data) -> {ok}`。写前先持久记录 pendingSave；版本改变时重读合并，最多三次，持续争用就保留 pending 并等待。布局接受已经可靠保存、但缓存写失败时，不回滚接受状态，之后可重试缓存。

文档已写成功、私有草稿尚未清理就退出时，重启能看到原保存意向；文档已等于目标则不重复写，只清理完成状态。若外部又改了同一值，三方合并保留冲突，不用旧 pending 覆盖它。接受 fingerprint 在写入期间变化，重新计算或留下缓存修复意向；不据过期缓存驱动视图。

真实磁盘文档测试适配使用不可变序号事件：并发写者争用同一个下个序号，只允许一个完整文件原子安装，另一个返回 CAS 失败。这证明**合作写者使用该适配**时的条件写策略；它不等于对普通 data.json 做到了跨工具 CAS，未适配写者也不会自动受它约束。

现有 Obsidian saveData 路径尚未替换，不能直接给其包装一个无实际条件检查的 compareAndSet 并标记通过。正式接入仍需确定私有权威状态/缓存边界、外部变更协调、设备隔离和失败语义，再验证宿主；未解决前，不能把此测试适配的保证外推给真机。
