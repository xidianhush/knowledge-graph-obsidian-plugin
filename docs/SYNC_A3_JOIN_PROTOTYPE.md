## 实现与复跑

`src/sync/persistence-prototype.mjs` 新增 `join({localData,choice})`、`getJoinBackup()` 和 `getJoinProof()`。localData 必须是调用方提供的本插件数据 JSON 对象，本模块不读取笔记/其他插件配置，也不修改原对象。choice 为 import/shared，或在空/相同布局时使用安全默认；有不同非空旧布局时须明确选择。

`normalizeLocalLayout` 可注入既有核心的隔离转换，输入/输出与原数据隔离；默认只认识 schema3（或没有布局的空状态），schema1/2 必须提供明确的核心转换，未知版本不当成空布局。`scripts/sync_join_check.mjs` 用仓库冻结的真实 0.0.9/0.0.10 核心生成 schema1/2 夹具，经当前 createLayoutStore.reconcile 隔离迁移，并对照原编辑后的世界坐标。

先 `npm test` 构建，再 `npm run test:sync-join`（等价 `node scripts/sync_join_check.mjs`）。这是独立真实文件/进程检查，要求支持硬链接的文件系统和子进程，和原 `npm run test:sync-disk` 分开。数据仅写 `.local/sync-016/a3/join/`，旧证据保留。本轮硬链接测试沿用工具审批在沙箱外执行，没有降级覆盖写。

## 加入不是先创建空接受状态

首次调用先保存**整个原插件数据的结构化 JSON 副本**及其 SHA-256，再记 join-backup 事件。保留语言、pipeline、UI、未知字段和原 schema/布局；它是 JSON 值的完整副本，不宣称保留原文件空格/键顺序等字节格式。单份仍受 8 MiB 与 JSON 护栏保护，超限不确认暂存、不改原数据。

加入未完成时 initialized=false、accepted=null；joining 元数据不冒认为已应用布局，保存协调器也不能用假的空接受状态覆盖旧缓存。即使转换失败、共享输入损坏、缺依赖或用户尚未选择，已完成的原数据备份仍可读出。

转换后检查完整 schema3 静态形状，原有每个组必须有一份转换/保留后的记录，不能通过丢组或回写空布局“迁移成功”。导入本机还需通过当前模型的完整身份/几何校验；明确使用共享时，旧布局可因当前结构变化而不适配，但其静态数据与备份仍须保留，采用的共享候选自身必须通过当前模型检查。未知本机版本依然停止，不静默降级。

未选择且本机为空：采用有效共享候选，不发空 reset/导入标记。未选择且非空布局与共享完全相同：可采用原共享记录，不重复生成相同值根操作。不同非空旧布局返回 join-choice-required，ID 尚未生成。

## 明确选择与导入操作

选择及规范化快照先记 join-choice。选择 import 时，先验证整笔操作可用且在 wire 预算内，再生成安全随机 ID；已知共享 ID 碰撞最多重试 8 次。所选 ID **先可靠写入 choice，再暂存导入 intent**，因此后续无论在哪个节点退出，都可重建相同操作。

导入操作的 parents 必须为空，只写本机完整旧布局的一份独立根。看见其他设备的旧布局不等于已经应用它，不能顺便把其他分支变成前驱。私有 import intent 使用版本 2（mode/source 额外字段），旧的普通 intent 仍保持版本 1；共享操作字段仍是原 v2，不加入本机迁移标记或原配置备份。

两端各自导入同组旧布局，会留下两条根与冲突；每端可确认自己的导入分支，但 sharedStatus=blocked 不代表整体同步已完成。无关联远端组也不提前算入本机 appliedIds，须随后通过普通外部接受流程。全局有合法并发或暂不适配的分量时，导入本机分支可保留；损坏/未知协议/缺前驱等不完整输入仍停止。

选择 shared 时不发布操作：完整候选正文与快照先存入本机，复扫/epoch 检查后写 join-adopt 事件，同时保留整个旧本机数据备份。缓存只能在接受完成后按协调器更新布局字段，当前 UI/设置/未知字段从新文档保留。

隐式“相同布局”选择在中断期间遇到共享布局变化，不能仍以原隐式选择覆盖旧本机布局：等待 renewed explicit shared 选择并写 join-consent。空设备原本没有布局可丢，恢复时仍可以采用有效共享，不制造清空记录。

## 凭据、重试和保持

导入成功的 accept 事件同时完成加入，getJoinProof 返回：

- joinReceipt：vault/installation、原数据与规范化快照摘要、选择和原操作摘要引用。
- importReceipt：与 A2 作者兼容的 `{version:1,vault,operation}`，仅导入模式存在。

两者只从本机已验证的日志和正文建立，未接受前为 null；复制来的 data.json 标记不能跳过备份、凭据验证或导入。getJoinBackup 返回隔离副本，外部修改返回值不影响原记录。

重复 join 不生成新迁移。原导入文件暂缺、正文被替换、 ID 在可靠选择后被其他正文占用时，保持备份/原 ID 并等待审阅，不换 ID、不覆盖其他文件；采用共享后仍检查全部已接受记录是否缺失/变更。已经完成的旧格式导入不会因为当前标题变了就重新迁移，旧配置也不能复活随后已确认的 reset；正常结构修复留既有专用作者处理。

本机布局在备份/选择后改变时停止原导入，防止用旧目标盖掉新编辑；UI/设置等非布局改变不会被旧备份回写。等价 schema3 布局仅本机 revision 改变也不造成重复导入。恢复时调用方必须提供可信的当前 localData，并由 getEpoch 覆盖会使候选过期的变化；正式宿主来源尚未接入，不能从本测试推断任意复制配置都能分辨设备。

已选好的 import 通过 join 原入口恢复，以重新核对本机源；不能绕过该核对调用普通 publish。普通 cancel 也不假装撤销整个首次迁移，返回审阅要求，原备份/操作保留；关闭、切换、恢复备份和改选的完整持久生命周期/产品 UI 仍待后续。没有静默删除已发布记录或原库的逻辑。
