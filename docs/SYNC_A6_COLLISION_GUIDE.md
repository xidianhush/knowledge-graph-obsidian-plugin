# SYNC-A6 坚果云同路径竞争

本包是合成文件取证探针。两端从同一份基线出发，断网后故意改写同一个物理文件，再观察坚果云的处理。探针使用候选的 attempts-v1 扫描器，并记录实际路径、SHA-256 和原始字节。它提供文件检查命令，运行时无需打开图谱。

## 准备

1. PC 将新包解压到短路径（例如 `D:\C6\`），打开其中的 `Knowledge Map A6 Collision PC`；iPad 打开 `Knowledge Map A6 Collision iPad`。保留库名和隐藏的 `.obsidian`。启用 **Knowledge Map A6 Collision Probe**。
2. 仅在这两个测试库安装、登录 Nutstore Sync，选择新的空远端 **{{REMOTE}}**，确保与日常库和此前目录互不包含。选择双向同步，关闭实时、启动、定时同步，配置目录设为不同步，排除规则 `SYNC-A6-Collision-*.json` 启用。允许 `Knowledge Map Sync/` 中的文件同步。
3. 保留当前的坚果云冲突处理策略，先记录两端策略名称。策略也会影响本轮结果，回传时请一起说明。
4. PC 手动同步一次，再 iPad 同步一次，等两端都完成。确认同步明细没有错误。两端各运行 **「A6 同路径 · 1 · 确认同步基线」**，均应提示基线已确认。

## 断网改写

1. 两端实际断网。PC 断开 Wi-Fi/网线，iPad 开启飞行模式并确认 Wi-Fi 已关闭。
2. 两端各运行一次 **「A6 同路径 · 2 · 离线改写同路径并导出」**。它故意覆盖本轮的同名合成基线，PC 写 PC 正文，iPad 写 iPad 正文。每端只执行一次。
3. 每端会自动生成一份 `SYNC-A6-Collision-端别-时间.json`，留作“离线”报告。预期各端只有本机正文，文件检查显示阻塞，因为新字节与原文件名里的基线摘要不同。

## 恢复联网并观察

1. 恢复两端联网，确认自动同步仍关闭。PC 手动同步一次并等结束。先记录坚果云的实际上传/冲突明细，再运行 **「A6 同路径 · 3 · 检查实际文件并导出」**，将报告标为 PC-首次上传后。
2. iPad 手动同步一次。若出现冲突处理选择，先截图完整选项，再运行检查导出，保留选择前的现场，并暂停这一轮。请将选项发回，下一步再按实际情况继续。
3. 若同步自动结束，记录明细并运行检查导出，标为 iPad-同步后。随后 PC 再同步一次并检查导出，标为 PC-往返后。
4. iPad 再同步一次并检查导出，标为 iPad-往返后。此步骤用于确认 PC 最后一次同步产生的文件是否又传回 iPad。
5. 若同步自动完成且没有待选择的冲突，两端完全退出 Obsidian，重开各自测试库，各运行检查导出，标为 PC-重开 / iPad-重开。

本轮观察坚果云实际留下哪些文件，可以出现副本、合并正文或替换。记录实际结果即可。探针扫描会检查当前文件是否满足摘要、正文和命名规则，并报告阻塞原因。原文件被服务替换过的事实要结合两端离线证据核对，单次扫描无法还原从未见过的内容。

## 回传

完整流程共 8 份报告。PC 的 4 份为离线、首次上传后、往返后、重开。额外导出的现场报告请注明阶段。

iPad 的 4 份为离线、同步后、往返后、重开。文件默认写在各库根目录，PC 可提供测试库路径，iPad 可以分享或打包 JSON。附两端冲突策略名称、同步明细，以及出现的实际副本文件名。报告保留尝试目录内每个小文件的原始字节，未知名称也会收录。若副本出现在其他目录，另外附上文件与相对路径。

文件过大、目录条目过多或盘点时文件变化时，先保留报告和原文件。本轮的物理路径覆盖仅用于独立合成库的传输实验。正式 v2 发布门禁保持关闭。
