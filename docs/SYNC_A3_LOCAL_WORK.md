# SYNC-A3 禁用后本地工作与兼容恢复草稿

2026-11-08，第八阶段技术原型。A3 仍进行中；此入口没有接入正式插件界面或修改日常库。上一阶段见 [关闭/容量](SYNC_A3_LIFECYCLE_BUDGET.md)，私有配置基础见 [配置协调](SYNC_A3_PRIVATE_CONFIG.md)。

## 实际缺口与本轮行为

此前 disable 排空并关闭会话后，私有后端只能在连接 enabled 时打开，不能继续保存本地设置/布局。现在明确 openLocal 可用同一 installation、同一逻辑库、同一签名日志，在连接仍 disabled 时打开本地会话。默认 open 仍只返回 disabled，避免关闭/切换后的重启自动打开存储；宿主需选择本地工作入口。

设备层 acquireLocal / assertLocalConnection 要求连接 disabled 且目标库一致，使用原设备排他锁、签名和进度锚；活动同步会话与本地会话不能同时占有。待完成关闭/切换意图仍先恢复，不绕过生命周期槽。

会话 access 固定为 local-only：initialize、join、stage、publish、cancel 和 acceptExternal 在队列及任何共享读取/写入之前拒绝，不把禁用变成“发布失败但已记录发布意向”。旧 outbox 保留原 ID/正文/attempted 标记。本地打开只验证/恢复原私有日志，找不到接受凭据时不制造空布局或自动加入；宿主必须转明确恢复/加入流程。

生命周期增加 local-ready / local-paused / local-join-required；runLocal 与只读 readLocal 使用原控制器顺序。openBundle 必须接收 access，构造相应设备绑定存储与会话；本地工厂误返回同步会话会在打开前拒绝并清理。工厂不得把原设备、raw store 或共享写入口交给 UI 绕过控制器。

## 本地设置、布局与重新启用

`src/sync/local-work-prototype.mjs` 提供窄宿主入口：设置开始/更新/保存、单项 UI 保存、布局保存、读取、兼容导出和恢复预览/确认。它没有正式 UI、Obsidian saveData 或外部配置文件写入。

设置/UI 继续写私有有效配置；布局写独立 layoutDraft，保留基线 fingerprint。布局经静态 schema3 校验和现有核心的隔离 apply/reconcile 检查，输入排队期间图谱 epoch 改变则 held。读取时再次验证基线与当前图谱，无法应用时返回 held，保留原草稿。成功写入后可重开读回本机布局；接受凭据与共享历史不因此改变。未保存设置仍以单独草稿返回，不混入已保存有效配置。

明确 enable 会冻结新本地输入、排空和关闭本地句柄，再启用连接、重开同步会话。设置/UI、布局草稿和旧 outbox 保持，**不自动发布本地草稿**；后续外部接受仍会被本地布局草稿阻挡，待 A4/A5 明确转换/冲突交互。软容量触顶仍可读、导出、关闭；未准入写返回 held，不能显示“已保存”。

## 兼容文件与明确恢复

exportCompatibility 要求调用方提供明确 destination、固定随机 id，且 destination 必须具备完整不覆盖创建语义。写 `<id>/data.json` 并读回，再写 `<id>/manifest.json`；清单绑定正文 SHA-256/UTF-8 字节数，scope=`compatibility-data-not-acceptance`。正文含本机已保存设置/UI/未知字段及当前可应用的本地布局草稿（如有），否则使用已接受布局；不混入未保存设置或待发布操作候选。单份 8 MiB 上限，超限不截断。

同源/id 可幂等重试，同名不同正文拒绝并保留原文件。中断片段没有完整清单时不能宣称导出完成。readCompatibilityExport 校验清单字段/范围、大小、摘要与有界 JSON 后只返回普通数据，**不产生接受账本、设备身份或自动导入权限**。这使用注入的完整创建契约，尚无 Obsidian/iPad 最终文件安装实测；A4 的 iPad copy P1 限制同样适用。

第八阶段的恢复入口先支持明确提供的 schema3 兼容 JSON。prepareRestore 验证设置版本、当前图谱和数据，返回本句柄内的预览 token，尚不写日志。applyRestore 再核对配置版本、接受 fingerprint、图谱 epoch；已有设置/布局草稿、保存意图、UI 待写或 outbox 时保持并 held，不覆盖。确认后以**一个 local-state 事件**同时保存完整原 JSON、设置草稿、布局草稿；有效设置、UI、根元数据和接受凭据保持。旧文件中的设备标记等只作为原文归档，不能授权连接或伪造接受事实。

恢复的设置需另行保存，布局为可读回的本地草稿；跨设备共享发布仍需后续明确动作。token 不可伪造、复用或跨重开；预览过期要求重新预览。图谱在持久提交后改变时返回 staged-deferred，保留草稿供重查。完整原文保留在私有日志，可能包含私有配置，不进入公开包。

协调器 local-state 升为 version 2，增加 restoreSource；原 version 1 在内存中无损映射，打开不额外写日志，首次保存才写新版。未知版本拒绝。恢复原文和两份草稿合并后仍受原单条 8 MiB 限额，超限不保存部分结果。

第八阶段当时尚缺旧 schema1/2 的恢复入口、丢失设备凭据/数据库后的信任重建、全私有数据库备份导入、直接覆盖 `.obsidian/.../data.json` 或旧版插件就地降级。schema1/2 的既有明确首次加入迁移原型保持；恢复入口遇到旧/未来 schema 保留输入并拒绝，不能静默丢组。导出后的手工旧版使用需后续独立流程，不能视作已验证降级体验。

## 旧版布局与私有存储缺失后的恢复（2026-11-09）

恢复预览接受明确提供的 schema1、2、3 布局。对 schema1/2，先用现有图谱核心试套原布局，确认当前图谱能完整接收所有组。再在另一份隔离模型中转换为 schema3，并检查组键、点 ID、坐标和图谱结构。需要改名、几何修复或缺少组时暂停。历史 0.0.9 和 0.0.10 核心生成的夹具均保持世界坐标。确认前重新检查预览内容、当前图谱和配置版本，再以同一私有事件保存完整原文及两类草稿。

宿主若明确预期已有设备身份，可以用 `requireExistingIdentity` 打开，缺失时暂停。判断已有身份需要由宿主提供本地依据。设备身份与私有记录同时消失时，宿主仍须让用户明确选择新设备或其他恢复来源。若设备身份仍在，日志锚对应文件缺失与内容不符分别标为 `private-anchor-missing` 和 `private-anchor-mismatch`，旧会话保持待恢复及原进度锚。

备份可通过 `prepareCompatibilityRestore` 从只读来源读入。先校验兼容包清单、正文长度和 SHA-256，再进入原预览与确认流程。隔离用例模拟原设备丢失私有日志，由另一设备身份通过现有明确加入流程读取共享历史并建立自己的接受状态，然后恢复兼容备份为本地草稿。恢复保留新设备刚建立的接受状态和共享记录。正式宿主需要接上暂停提示、备份选择及重新加入交互。分片回查包仍按原范围供人工查阅。

新增五项隔离检查，包括两个实际旧版核心生成的坐标用例、拒绝不兼容布局、缺失身份门禁及从私有日志丢失到另一个会话恢复草稿。默认构建与 21 个脚本、六套真实磁盘回归均通过。同步细项合计 481 项，包含 96 次实际进程退出。存储丢失新用例使用隔离替身，正式宿主和新流程真机验证待做。证据 `.local/sync-016/a3/local-work/legacy-recovery-verification.json` 与 `legacy-recovery-regression.log`。

## Knowledge Map 恢复宿主候选（2026-11-09）
