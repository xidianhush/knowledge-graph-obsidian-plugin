## 实验数据边界

第一步实验 envelope 仅有 `protocol`、`vault`、`id`、`parents`、`changes`。当时协议试验值为 1，vault/id 使用 32 位小写十六进制；当时仅校验标识，后续作者已补安全随机 ID，正式实现契约使用文末 v2 形状。

`parents` 是操作实际依赖的前驱 ID。索引不使用墙上时间、本机 revision、设备优先级或到达顺序。后续写入层必须确保前驱代表用户实际基于的布局，不能把“已扫描但未应用”当作依赖确认。

`changes` 是同一次操作的完整数组，每项由 `group` 和 `value` 构成；`value` 为 JSON 对象或 null。null 表示保留的逻辑重置标记。因果索引本身仅验证有界 JSON；schema3 规划器另要求下文的结构包装并验证身份与当前几何。所有身份键不用于文件读写；这仍不是最终布局记录格式。

同 ID 的对象键顺序差异视为同内容；数组顺序保留，数组内容不同会按内容不一致处理。不同内容的同 ID 或可识别同库同 ID 的无效副本会隔离该 ID 的所有副本，依赖它的记录继续等待，不挑一份静默使用。原输入仍由调用方保留，本索引没有删除或持久化能力。

## 输出与已经成立的性质

`ready` 保留依赖齐全的整笔记录，`pending` 保留缺前驱/循环依赖记录 ID，`quarantined` 标出禁止使用的 ID，`issues` 给出输入问题。ready **只表示依赖齐全**，不表示可以安全写入布局。

`frontiers` 给出每组尚未被同组后继覆盖的操作头，`conflicts` 列出多头组；`heads` 是依赖图整体操作头。不同组可并存；同组并发保留两版。仅引用其中一头的后继不会把另一头静默丢掉；同时引用两头的新记录可以成为新的共同后继。

索引保留多组记录的整个 changes。新增 schema3 规划器会计算保守的冲突关联分量，生成完整分量候选；没有生产持久化/视图提交，不能从 ready 直接套用某个组片段。

缺失/乱序通过对当前完整集合重新分析处理；重复输入幂等，所有四节点 DAG 的 24 种排列结果相同。缺前驱、循环和未知协议不进入 ready。重置标记不会因旧祖先晚到而消失，并发重置/编辑仍保持冲突。

## 输入防护与临时限额

第一步当时的实验护栏为最多 1000 个输入、单条 256 KiB、总计 8 MiB、每条最多 64 个前驱/128 个组；JSON 限深 16、遍历节点 20000，并限制字符串、对象键和数组长度。资源阶段已调整，见文末当前预算。拒绝非有限数值、getter、循环对象和巨大稀疏数组；在编码过程中检查单条字节预算。操作数或总字节超限会直接拒绝本次分析，不返回已处理子集冒充成功；调用方负责保留全部原输入并提示暂停。

这些数值是原型防护上限，**不是正式性能预算，也没有经过 iPad 规模验证**。因果祖先集合目前可能需要平方级内存，A2 后续必须用真实布局与长链/并发数据测量并决定算法和预算。

## 第二步：真实 schema3 校验和完整事务候选

`planSchema3Transactions(input, {vault, baseline, createModel})` 接收完整记录集合和本机可信基线。基线须为带本机 revision 的 schema3，且与当前模型严格兼容；不兼容会拒绝计算，不覆盖原数据。revision 只保留在候选中，不用于跨端判新旧，也不在此步递增。

第二步 change.value 的实验包装为 `{schemaVersion:3, record, structures}`，null 继续表示重置。record 来源于真实 createLayoutModel.capture → createLayoutStore.command 的规范 schema3；每个 heading 组携带所属 note 的完整 structures 快照。此包装现仅为内部输入和 v1 测试兼容形状；资源阶段新作者输出改为文末的 v2 去重候选，不能继续把重复包装当作共享文件格式。

静态检查包括：规范节点键与相对路径（拒绝绝对路径、反斜线、空段和 ..）、组成员、shape/points 顺序/唯一性/有限数值、repair 元数据、完整身份表、同 note 引用、父级先于子级和 level 关系、结构摘要格式/数量。单笔操作任何 change 无效都会隔离整笔 ID，并让依赖它的后继等待；同 ID 不同 schema 副本不会按到达顺序选赢家。因果索引新增可选的纯验证回调，传入副本，复用此隔离语义。

createModel 必须每次创建一套隔离节点模型。`probeSchema3Snapshot` 使用既有 core apply 检查边界、圆重叠、半径/结构摘要与父级局部坐标，再用 reconcile 作精确身份上下文对照；**不发布 reconcile 的修复或改名结果**。缺笔记/组、结构不符或有限但非法几何都保留在索引中，整个关联分量暂不生成新状态，等待内容或后续协调。这里采用严格兼容模式，旧结构/正文证据变化/改名与跨端排序差异仍须后续沿用既有保守迁移契约，不能直接接入生产保存路径。

事务策略是可审阅的保守草案：历史上同笔操作涉及的组，以及共享同一 note 身份表的组，形成关联分量。任一组有冲突时，该分量保留调用方原基线；分量外的独立组仍可生成候选。历史关联可能扩大暂缓范围，后续可在证明不拆散操作的前提下优化，不能当成用户已验收的最终冲突体验。

解决冲突的新记录必须确认全部相关前驱，且显式携带整个历史冲突分量的组结果（需要清除的组写 null）。仅解决 A 而遗漏同笔 B 的记录会被标 `layout-incomplete-resolution`，后继不能借它绕过冲突。该规则也覆盖通过历史 A+B、B+C 形成的传递关联，以及共享 note 身份表的关联。

输出 proposal 是纯内存 schema3 候选，与输入/基线/索引记录分离。decisions 区分 candidate、conflict、incompatible；若有缺依赖、无效、冲突或不兼容，总 status 为 blocked，即使独立分量有候选，也不代表整体已同步。**此模块不提交磁盘、不更换任何图谱视图、不改变本机 undo 栈**；A3/A4 要再协调可靠写入与原子可见性。

第二步当时的布局规划器护栏为 128 条输入、256 个关联组、5000 个坐标、每 note 5000 个身份行、每组最多 128 siblings，基线 256 KiB。资源阶段已优化并调整输入/字节限额，见文末；组/坐标/身份边界保持。超预算拒绝本轮、原输入保留；这些限制不是 iPad 性能承诺。

## 第三步：操作作者、撤销保护和首次加入

`createLayoutActionAuthor({vault, createModel, nextId})` 是单个本机发布者的纯内存原型。每次调用提供 context：完整可用 records、实际已应用的全部 appliedIds、本机 localBaseline，以及 sharedScanComplete。作者检查已应用集合因果闭合、其投影与本机布局一致；没有完成共享扫描时拒绝生成记录。记录的 parents 只取已应用集合的前沿，不把仅收到/看到的记录当作同意覆盖的依据。扫描和实际应用的事实仍须 A3/A4 适配层提供，纯函数只能检查这些声明的内部一致性。

### 发布确认边界

prepareEdit/prepareResetGroup/prepareResetAll 生成 operation、proposal 和下一步 appliedIds，不推进历史。作者一次只保留一笔 pending；retry 返回同一 ID/内容的新副本，不再次生成 ID。调用方可靠保存记录并应用候选后，才调用 confirmPublished；该方法核对记录内容及已应用状态后生成历史令牌或导入凭据。

确认失败不会清 pending 或消耗撤销令牌，未发布的动作可以 cancel，发现记录已发布时不能假装取消。**这些都是内存状态检查，没有执行真实写盘或证明云端送达**。备份、outbox、模糊写入结果、崩溃恢复和跨视图 owner/busy 协调留 A3/A4；真实结果未明的写入不能仅凭旧扫描视为未发布后取消。

### 重置与撤销/重做

单组重置生成 null tombstone；重置全部只覆盖已应用集合中当时已知的组。无保存覆盖或内容未改变时不生成空记录；新设备的空状态不清空已存在的共享记录。未应用/未见的新增组与重置并发存在，不被隐式写入父链后丢弃。

撤销/重做用新的操作 ID 和当前实际已应用前驱发布反向结果，不删旧文件，也不递减 revision。撤销能力来自作者本机会话中的不透明对象令牌，仅在确认发布后生成，最多保留 50 个；重载作者后失效，不能从远端 JSON 或伪造字段制造“本地可撤销历史”。令牌绑定原操作完整内容；相同 ID 被换内容也会拒绝。

执行历史动作前检查整个相关事务/note 分量的当前前沿。远端同组或相关组更新，无论已应用还是仅收到，都阻止过期历史；独立组更新不强制清掉有效历史，也不会被顺手加入本次前驱。结构/几何上下文不再匹配时拒绝生成旧操作，基线不变。

连续撤销/重做会产生新的本机 ID，不能把本机确认过的反向操作误判成远端覆盖。作者仅在确认本地 undo/redo 后、目标状态已恢复且所有相关后续写入都能证明来自本机会话时，更新先前令牌的前沿保护；任何相关远端写入都不授予该更新权限，即使它写的是完全相同的坐标。新编辑/重置确认后才清 redo，失败/取消不提前清理。这个保守策略仍需 A5 的体验审阅，并未接入现有运行插件的 undo 栈。

### 首次加入与旧布局导入

prepareJoin 必须先完成共享扫描。空本机只给共享布局采用候选，不发布“空布局”。有不同本机旧布局时，默认返回 join-choice-required 并保留备份预览；只有调用方明确选择 shared/import 才继续，不能在默认分支中覆盖旧布局。共享本身有冲突时不自动采用。

选择 import 会保留完整本机 backup 预览，并生成独立根记录（parents 为空），使两端旧布局按同一冲突规则并存；看到远端记录不能让旧布局导入自动变成其后继。发布确认后返回本地 importReceipt，内含 vault 和原导入记录。A3 必须在真实写入前可靠保存备份，并持久保存凭据；本原型并未创建备份文件或修改 data.json。

在新作者实例中提供该凭据，可核对共享记录与原始快照并避免重复导入。记录暂未同步到时返回 review-required，不生成第二条迁移；错误库、被替换内容或不同旧快照均拒绝。配置被复制到另一设备时也不能只因存在某个标记就跳过不匹配的旧布局。冲突未解决但能验证自身导入分支时保留该分支的已应用集合，不冒称整体一致。

### ID 与边界

默认 ID 使用 Web Crypto 的 16 字节安全随机数，不依赖设备配置计数器、时间或本地 revision；与已知集合撞 ID 时最多重试 8 次，否则拒绝，不覆盖。测试可注入 nextId，生产接入须沿用安全随机源。此步解决操作 ID，正式共享 vault 标识的首次连接/导入生命周期仍需 A3。

作者复用临时输入/快照预算，历史令牌和本机来源证明也有界；准备、确认、重试、取消和输入/输出均隔离。资源阶段已减少结构表重复复制、比较与校验；仍无 iPad 性能结论。

## 资源阶段：v2 去重候选与有界索引

新增 `src/sync/wire-prototype.mjs`。新作者输出为 `{protocol:2, layoutSchema:3, vault, id, parents, changes, structures}`；`changes` 仍是整个操作的事务边界，但非 null 的 `value` 直接是 schema3 record，`structures` 在操作顶层按 note key 只存一份。null 仍是 tombstone。传输版本 2 与布局 schema 3 独立；不加入时间或 revision 作为胜负依据。不在不同操作间引用外部结构表，防止新增另一种缺文件依赖。

内部按需展开为原验证形状，多个组引用同一只读结构表；同 note 表内容冲突、缺失/多余表、未知 schema/version 均隔离整条操作。接收端仍通过身份与真实模型的几何/协调检查。v1 仅保留实验测试兼容，同 ID 的 v1/v2 即使投影相同也属于不同不可变正文，不能替换原文件。字段键排序允许等价 JSON 属性顺序去重，不按字节原序误报冲突。

因果关系改为拓扑位图，1024 条上限的祖先位矩阵最多 128 KiB（不含 Map/ID 和其他索引）；冲突前沿沿父状态递推。候选优先对全部无冲突分量合并 probe 一次，失败时再逐分量定位，保留独立可用分量。身份行只在一次规划调用内按已清洗结构表引用缓存校验，组成员检查仍逐组执行；不跨调用缓存不可信输入。

当前原型预算为 1024 条输入、单记录 2 MiB UTF-8、单本机快照 8 MiB、输入正文总计 32 MiB、每操作 64 parents / 128 changes；布局 256 个关联组、5000 个坐标、每 note 5000 行身份、每组 128 siblings。JSON 限深 16、遍历值 200000、单字符串 16384 UTF-16 单元、键长 2048、单数组/对象最多 8192 项。正文编码在遍历过程中计算 UTF-8/转义字节；快照与传输预算分开，不把更大的本机基线自动变成可发送记录。

超记录/损坏条目隔离其可识别 ID，后继等待；操作数/总量/候选布局超限抛出并暂停整轮，不能返回前一部分当成一致结果。A3 必须保留本机布局、备份、原输入和未发布记录并显示明确状态，不能为继续同步而截断历史、丢弃 tombstone 或自动 GC。1024 条/32 MiB 是原型保护线，**不是可无限使用的生产容量**；大笔记每次操作仍重复该 note 的身份表，64 次历史实测已约 13.95 MB。可靠历史归档/压缩未实现，触顶处理是接入/发布门禁之一。

资源阶段提出的目录方向现已在 [v2 实现契约](SYNC_PROTOCOL_V2.md) 定稿：普通目录 `Knowledge Map Sync/v2/<vault-id>/ops/<operation-id>.json`，两种 ID 均为 32 位小写 hex。首次创建/加入需处理多个候选和同时启用，不靠“最新”目录或可覆盖的单一 marker；持久化实现留 A3/A4。本轮不改用户配置或迁移 A1 哨兵。

## 资源测量事实与限制（2026-11-08）

复跑：先 `npm test` 构建，再 `node scripts/sync_scale_benchmark.mjs <label>`；输出到 `.local/sync-016/a2/scale-<label>.json`。该脚本是可选基准，不以易波动的毫秒数作为 npm 门禁。Windows / Node v24.18.0、i7-13700H，按用例开独立进程，V8 old-space 256 MiB，20 秒进程超时；每例一次首次调用加三次热调用，中位数取后三次。V8 限额不等于进程 RSS 限额，RSS 包含建图/夹具/临时序列化；调用后的 heapUsed 是采样值而非峰值。建图和夹具准备不计入函数耗时，但计入进程超时和峰值 RSS。

初测 `scale-baseline-fixed-fixtures.json` 揭示原 256 KiB 单条预算容不下 4097 节点/32 组和同 note 多组导入；后者重复身份表达到 4,358,619 B。`scale-optimized.json` 的 4842 节点用例仍触发 20 秒整例超时，单独 profile 复现热导入约 5.36 秒；消除重复结构比较/验证后才通过最终轮。初测失败保留，不能算通过。

最终 `scale-final.json` **15 个用例全部完成，四次调用均未抛错**；64 并发分支用例预期返回 blocked/保留冲突，而不是强行成为可应用候选。其余布局/导入候选均通过真实模型 probe。主要结果：

- 1000 条元数据长链：热中位约 32.2 ms，进程峰值 RSS 64.9 MiB；同机初测约 85.9 ms / 131.5 MiB。1024 条小布局长链约 64.9 ms；128 条作者 reset 准备约 47.2 ms。
- 128 siblings 导入约 16.1 ms；4097 节点/32 组导入约 437.5 ms，传输 1,514,633 B、进程峰值 RSS 280.0 MiB。
- 一 note / 1020 headings / 20 组：传输从 4,358,619 B 降到 421,693 B（约减 90.3%），热导入约 173.2 ms。
- 一 note / 4840 headings（共 4842 节点）/ 40 组：传输从展开形状 40,703,350 B 降到 2,017,444 B，已接近 2 MiB 记录上限；热导入约 1255.6 ms，进程峰值 RSS 326.9 MiB，GC 后 heapUsed 约 14.8 MiB。64 条单 note 1020 headings 历史约 13,950,367 B、规划约 336.2 ms、峰值 RSS 317.6 MiB。不能据少量 GC 后采样宣称无泄漏。
- 本地 1000 个小 JSON 文件枚举/读取/解析热中位约 65.5 ms；这是 Node 文件系统与暖 OS 缓存，不是 Obsidian Vault API、Nutstore 网络耗时或 iPad 结果。

所有夹具均为合成笔记经现有 build/capture/store 生成。密排节点不一定允许单节点平移，因此部分夹具用刚性旋转兄弟圆心并平移子树构造有效布局；**不是原生拖动性能或全部节点可拖动证明**。优化轮还去掉了夹具生成时不相关的 store 撤销历史保留，规模夹具 RSS 不作严格优化前后 A/B；元数据长链夹具相同。大规模成本说明不能在每帧或频繁 UI 保存时全量导入，A3/A4 必须合并请求、避免交互期间长任务；iPad CPU/内存、大文件过滤和网络成本全部留 A6 实测。

新增 `sync_wire_check` **11 项**（含 12 个确定性 DAG 与独立 Set 参考对照、1024/1025 条边界、长分支完整/部分解决、新旧格式/真实坐标、损坏和别名隔离、UTF-8）；`npm test` 构建 + **15 脚本通过**，同步细项共 21 + 25 + 35 + 11 = 92。日志 `.local/sync-016/a2/resource-regression.log`，摘要 `resource-regression-summary.json`。运行 main.js 保持 416,150 B / SHA-256 `8801c3a3e5c2d96fcd6d230e8b703eac8472ac815e677e915c81c23249411391`。
