# SYNC-A4 坚果云单向接收测试

本轮由 PC 投放两个合成布局文件，再通过 Nutstore Sync 逐步传到 iPad。iPad 保持图谱打开，只同步和观察。样本 2 所需的笔记稍后单独传输，用来验证布局与笔记分开到达时的表现。

## 两端准备

1. 在 PC 和 iPad 上分别解压同一份 ZIP，将 `Knowledge Map A4 Nutstore` 打开为新库，启用同名测试插件。iPad 解压时保留隐藏的 `.obsidian` 目录。
2. 仅在这两个测试库安装并登录 Nutstore Sync。新建一个空的坚果云目录，例如 `/KM-A4-1109`。在选择器的「新建文件夹」名称框只填 `KM-A4-1109`，创建后进入该文件夹，再确认底部当前路径为 `/KM-A4-1109`。两端选这个目录，确保它与日常库及之前 A1 测试目录分开，且互不包含。如果日常库同步整个 `/`，请先停在这里确认隔离方式。
3. PC 选择「仅发送」，iPad 选择「仅接收」，都使用名称不带「覆盖云端」或「还原本地」的模式。两端关闭实时、启动和定时同步，并将 `.obsidian` 设为不同步。保留 `Knowledge Map Sync/` 下的 JSON 和 `Synthetic/` 下的 Markdown 可同步。首次同步若有操作预览，确认只有合成库文件和预期的上传或下载。[Nutstore Sync 1.6.0 官方说明](https://github.com/nutstore/obsidian-nutstore-sync/blob/1.6.0/README.md#-按你的方式同步)
4. 两端打开「从当前库构建知识图谱」，各保留一个图谱标签页。先 PC 同步一次，再 iPad 同步一次，作为基线。图谱此时只有 `Arrival` 笔记及其标题。保持 iPad 在 Obsidian 前台，测试期间用选中或缩放观察，布局拖动会生成私有草稿并暂停接收。

如果根目录选择器创建时报 `400 Bad Request`，可先用短名称重试一次。若仍报错，用坚果云网页端或桌面客户端新建独立的空同步文件夹，再回插件选择已存在的目录。使用客户端时，将它绑定到专门的空目录，避免客户端和 Nutstore Sync 同时同步同一个本地 Obsidian 测试库。[坚果云客户端创建同步文件夹说明](https://help.jianguoyun.com/?p=1447)

## 按顺序传三次

1. **传布局样本 1。** PC 运行「A4 · 投放布局样本 1」。PC 跑完 Nutstore 同步后，iPad 再运行一次。iPad 关闭同步结果面板，预期自动出现「布局已应用（1/2 条操作）」。图谱原位更新，视角和选中项保留。
2. **只传布局样本 2。** PC 运行「A4 · 投放布局样本 2（笔记先不添加）」，再按 PC 同步 → iPad 同步的顺序操作。iPad 预期提示「布局正在等待兼容的图谱」，图谱保持样本 1 的布局。请在看到此结果后再添加笔记。
3. **单独传迟到笔记。** 只在 PC 运行「A4 · 添加迟到笔记」。再次 PC 同步 → iPad 同步。iPad 预期出现 `Late` 笔记，图谱重建并自动显示「布局已应用（2/2 条操作）」。

三次投放和添加笔记的命令都只在 PC 上执行。iPad 每轮可以截图保留 Nutstore 下载明细，尤其是第二轮的 JSON 和第三轮的 `Synthetic/Late.md`。

## 回传结果

- 跑完后两端各运行一次「A4 · 导出本机测试报告」。文件在测试库根目录，名称以 `SYNC-A4-native-` 开头。PC 可提供测试库路径，iPad 可直接附上 JSON。请附上 iPad 各轮看到的提示，若方便也可附下载明细截图。
- 如果 iPad 同步结束后没有自动更新，先查看 Nutstore 下载明细并导出当时的报告，再点一次「A4 · 检查已到达的布局文件」。请注明在哪一轮用了手动检查，以及检查前后各显示什么。如果仍卡住，先保留这一步的报告和提示。
- 若任一端的 Obsidian 或 Nutstore 版本和上一轮不同，请附版本号。报告和截图只需包含测试库内容，账号、密码和 WebDAV 配置留在本机。
