## 1. 目录和逻辑库连接

新写入目录为 `Knowledge Map Sync/attempts-v1/<vault-id>/ops/<operation-id>.<sha256>.<attempt-id>.json`，相对当前 Obsidian vault 根目录。正文仍为 protocol2/layoutSchema3；连接及私有账本须绑定 attempts-v1 传输。vault-id、operation-id、attempt-id 均为 Web Crypto 16 字节随机数的小写 32 位 hex，不依赖时间、显示库名、绝对路径或已复制配置身份。已知路径碰撞最多尝试 8 次分配，一笔操作最多登记 4 条尝试路径，耗尽则保留原 ID/正文并暂停，不无限重写。**SYNC-UX-A1 修订（2026-11-24）**：默认图谱使用固定 vault-id `71e90242bea19488f2a16c60f78fcabc`（= SHA-256("KM-SYNC-DEFAULT-LAYOUT-1") 前 32 位小写 hex），仅标识各库内的默认图谱，使两端离线首次开启落在同一命名空间；operation-id、attempt-id 以及高级功能新建的其他图谱 vault-id 仍为随机。不同 vault 目录之间不扫描、不合并；设备身份、密钥、操作 ID 与私有账本继续独立。变更说明见 [SYNC-UX 设计](SYNC_UX_EASY_SETUP_DESIGN.md)。

旧 `Knowledge Map Sync/v2/<vault-id>/ops/<operation-id>.json` 保留只读/明确恢复入口，不继续按旧单路径方式发布。两个目录分别发现/核验，连接显式选择逻辑库和传输；不因正文协议相同而混扫合并。跨目录带入布局先保全备份、检查冲突/outbox，明确选择验证快照后作为新逻辑库根；旧历史和凭据原位保留，不伪造自动历史迁移。

不设置可被并发覆盖的单一共享 manifest 作为权威。**SYNC-UX-A1/A2 修订（2026-11-24）**：新增独立初始化目录 `Knowledge Map Sync/bootstrap-v1/<default-id>/<sha256>.<attempt-id>.json`，正文固定为 `{"version":1,"kind":"default-layout","transport":"attempts-v1","vault":"<default-id>"}`，不含设备身份、笔记、坐标或时间戳；采用统一规范化编码与正文摘要，attempt-id 用现有随机规则，文件不可变、独立尝试路径、写后读回校验，不引入可覆盖的权威 manifest。有效初始化记录使**空布局也可被发现**（连接候选标记 `bootstrapOnly:true`，已有布局操作的候选为 false）；两端生成的合法同正文记录按一个初始化事实处理，不构成布局冲突。初始化记录只允许发现默认图谱，**不能证明布局已经接受或另一端已经收到**。第一次开启时：只有一个有效可写共享图谱则自动选择；没有共享图谱则自动准备固定默认图谱、写入初始化记录后重新扫描再连接；发现多份图谱则展示一次易读的图谱选择（ID 放详情），不按时间或目录顺序选胜者；只有旧 v2 只读历史则说明只读状态并提供现有审阅/恢复路径，不自动改为可写。完整扫描、大小与数量保护、残片及摘要校验沿用现有保护原则；未知版本或损坏输入暂停自动流程，不能当作“没有图谱”重新初始化。仍**不发布 reset、清空操作或虚假编辑充当初始化标记**。默认宿主的旧 v2 只读重新加入不等于已实现新目录的正式发现/连接 UI。

两端同时新建可能出现两个 vault-id，必须明确选择/迁移，不能按“最新目录”自动合并或静默切换。**SYNC-UX-A1 修订（2026-11-24）**：默认图谱命名空间固定（见 §1），两端离线首次开启不再各自生成随机默认 ID，因此默认场景不产生双随机 ID；本条选择/迁移要求仅适用于高级功能新建的其他随机图谱。新设备不从同步来的 data.json 自动接受连接和已应用凭据。连接到现有命名空间必须走扫描、旧布局备份和首次加入流程。切换/关闭不删旧命名空间，不在日常库自动部署本契约；A1 的 `a1-probe` 保留原用途。

发送器只写规范独立路径，已知存在的路径不覆盖；此检查不提供针对外部竞争的原子排他保证。发布和接收都完整扫描选中受控目录，包括重复、残片与异名副本。合法异名同 ID 正文参与冲突识别，未知命名、损坏或不匹配正文保留并阻塞，不能静默略过。已见同 ID 异正文隔离事实须持久保留，删除其中一份不自动解除。group/path 只作布局身份，不成为任意读写目标。服务上传/过滤由用户同步工具管理，不从本机写入成功推定对端完成。

## 2. 不可变操作格式

根对象恰为 `{protocol:2, layoutSchema:3, vault, id, parents, changes, structures}`，字段不可增删；传输协议版本 2 与布局 schema 3 独立。

- vault/id 必须匹配上述 ID 规则，vault 必须是已选择命名空间。
- parents 为本机**已经接受并可靠记录**的因果集合的头，不包含仅收到、尚未接受的记录；不得重复或指向自身。
- changes 为非空数组，每项恰为 `{group,value}`，组键不得重复。整个数组是一笔事务。
- 非 null value 直接是 schema3 完整组 record，不重复包 `{schemaVersion,record,structures}`。structure 表在顶层 structures 中每 note 一份；所有非 null heading 组必须有对应表，禁止多余表。不同操作各自携带需要的完整身份表，不引入额外跨文件结构表依赖。
- value 为 null 表示该组的重置 tombstone。reset-all 只重置已应用前沿已知的组，不清除并发新增的未知组。操作种类不另外进入 wire 字段，edit/reset/undo/redo/import/reconcile 由其完整因果和变更结果表达；本机会话诊断可另存。

record 允许 shape/points，heading 组另有 note/structure，及既有 repair 元数据；复用核心规范、整组兄弟坐标及相对父半径，不使用屏幕像素。structures 是完整的标题 key/title/parent/level/evidence 表。组/节点键为 `root` 或规范 JSON 字符串 `[kind, relativePath, suffix]`，kind 仅 folder/note/heading。拒绝绝对路径、反斜线、冒号、控制字符、空段、`.`/`..`；按大小写、Unicode 原字符串精确匹配，不猜测路径或标题对应。

新写入采用有界 JSON 规范化：对象键排序、有限数值、UTF-8 编码。attempts-v1 的完整正文须为规范 UTF-8 字节且与文件名摘要/ID 相符，非规范字节不自动原地改写。逻辑同 ID 冲突按规范化正文判定，而不是把空格变化当另一个合法操作；未知命名或非规范/损坏输入仍可作为阻塞证据，不因规范化后相同就删除原件。规范正文不同则隔离该 ID 的所有副本、后继等待。纯核心 v1 实验夹具和旧 v2 只读适配保持各自用途；A1 哨兵不自动迁入新传输。

## 3. 一致性、冲突与应用

因果后继取代同组祖先；乱序记录等待前驱，循环或缺前驱不能应用。重复到达不产生新操作。并发同组版本全部保留，不能以设备时间、revision、相同坐标或接收顺序选胜者。不同无关联分量可并存；多组事务和共享 note 身份表形成关联分量，冲突时保留该分量整个已接受基线。完整解决必须显式写入历史关联分量的所有组并确认相关冲突前沿；部分解决记录隔离，其后继等待。

所有远端候选必须通过静态格式/身份校验、全局预算和当前隔离图谱模型的 apply + 精确 reconcile 检查。笔记内容、身份或配置范围暂不匹配时，保留记录并待协调，不能以自动布局/空布局替换共享真相。读取操作本身不发布新记录。

拖动/保存、未保存设置草稿、隐藏视图与后台恢复由 A3/A4 协调。保持既有平移/缩放、选择和交互；全量分析不可在每帧/每次 UI 保存执行。重建后使用最新输入重新规划，不把迟到候选覆盖新编辑。缺事件通过前台/重开补扫恢复，不整页 reload。

## 4. 本机作者、导入和结构修复

普通作者的输入必须包含可靠的本机已接受快照和因果闭合的 appliedIds；两者与共享历史投影精确一致。扫描完成不等于应用完成。先 prepare，再持久写入并可靠接受，最后 confirmPublished；失败 retry 使用同 ID/正文，不提前推进 undo/redo、导入凭据或已应用前驱。发布前可取消，发布后不得通过删操作来假装取消。

undo/redo 是新操作，最多 50 步本机会话令牌，不共享撤销栈；只撤本机确认过的操作。同组或历史关联分量出现远端新版本时，旧历史过期，即使远端值相同也不复活。结构修复确认后清除旧会话历史，不为自动修复生成可误用的撤销令牌。

首次加入先完整扫描。空本机只采用共享候选，不发布空重置。有不同旧布局时必须明确选择使用共享或导入本机；共享冲突时不自动采用。**SYNC-UX-A2 修订（2026-11-24）**：在用户开启布局同步的授权下，无歧义的首次加入自动完成——空本机采用共享候选（共享布局为空也可加入，不发布空重置）；本机已有手动布局而共享历史为空时，完整备份及严格校验后自动导入一次本机布局；两边布局语义相同时备份、核验后采用共享布局，不重复发布。两边已有不同布局或共享冲突时仍展示本机与共享预览，由用户决定，沿用现有保留分支与冲突解决机制，不直接覆盖任一方；本机旧布局存在校验问题时沿用“当前可用布局”审阅及归档保护，不自动丢弃不可用组。所有自动加入仍经过现有备份、指纹复核、图谱兼容性和写入门禁，不能用 UI 层直接改接受状态。导入先保留可靠备份，再发布 parents 为空的独立根分支；两端旧布局冲突由同一机制保留。导入凭据绑定逻辑库、原始操作及快照，重启时验证，记录暂未到达则等待/审阅，不能重复导入。

结构变化走 `prepareReconcile` 专用入口，普通编辑校验不放宽：

1. 使用静态历史检查核对**本机可靠接受凭据**：记录有效、前驱齐全、已接受子集因果闭合且无冲突，投影等于保存的旧快照。这个投影仅证明历史一致性，不是可交给视图的候选。
2. 文件/目录改名仅接受宿主明确的相对路径事件，最多 64 个有序事件；身份字段按路径段边界映射，不改标题文字。拒绝碰撞、路径穿越、删除事件和文件夹移入自身子目录。标题改名/增删仅使用既有核心 reconcile 的身份和可行性判断。
3. 使用当前隔离模型修复，保持每份原 override 有一份新或保留的记录。所有目标组能完整通过当前静态/身份/几何检查时，旧别名 tombstone 与新组记录放在**同一操作**，parents 只取已接受头；新历史投影必须等于完整修复目标。
4. 任一组无法验证时，返回旧基线、备份和包含独立局部修复的 preview，整轮不发布，不拆成部分成功，不把未知组写成 null。相似文件名不足以推定改名；删除整个组/笔记不自动变成共享 reset。缺内容恢复后重试。
5. 两端从同一旧状态自行生成修复，仍是并发操作，保留冲突；接收端只应用已发布的修复候选，不因收到或晚到内容再发布重复修复。A4 必须区分本机结构事件和接收后补建图。

本机可继续使用既有核心的局部恢复/自动布局预览；preview 不提升为已接受凭据。无法同步的新本机编辑由 A3 保留待处理草稿/基线，不得为满足作者接口而清空布局或丢失用户编辑；具体审阅/提示交 A5 产品验收。

## 5. 预算、保留与失败

当前工程保护线：共享目录最多 1024 个物理文件，重复/残片/副本均计入；单文件 2 MiB UTF-8；单本机快照 8 MiB；扫描正文总计 32 MiB。核心还限制 1024 条逻辑输入、每操作 64 parents / 128 changes、256 个历史关联组、5000 个保存坐标、每 note 5000 行身份、每组 128 siblings。JSON 限深 16、遍历值 200000、单字符串 16384 UTF-16 单元、键长 2048、单数组/对象最多 8192 项。重试也消耗物理配额；不能将 1024 份同笔副本的扫描证据称为 1024 次实际布局操作容量。约 5000 图谱节点不保证任意标题/历史适配单条记录。

超操作数/总正文/关联组/坐标预算，暂停整个分析，不返回已处理子集冒充完成；单条无效/未知协议/同 ID 冲突隔离并阻止其后继。A4 读取前应先限制文件数量/大小；部分 JSON 或未知正文无法解析时，保留原文件和本机快照，对可从规范文件名识别的 ID 保持阻塞，不能悄悄略过后继续发布。预算失败、磁盘失败或结构不兼容都不触发丢弃输入、重写空目录或覆盖原文件。

初版不自动 GC、压缩、裁掉 tombstone 或删除“旧文件”。1024 物理文件/32 MiB 不是无限生产容量承诺。接近上限须明确提示；触顶保留已可靠保存的本机状态、原记录和 outbox，暂停发布/合并。私有预算也可能阻止新的本地保存，失败须明确显示未保存，不能承诺无限本地编辑。受控导出/恢复、新逻辑库轮换及旧离线端返回的流程须按正式评审第 6/7 节实现并验证；未实现前不宣称一键归档，不能静默删除真实历史放行。

Windows/Node 资源实测是选取这些保护线的依据，不是交互延迟或移动端内存保证。新增近 5000 标题修复约 3 秒、进程峰值约 367 MiB，因此 A3/A4 必须合并工作、避开交互和防止重复全量运行；iPad CPU/内存、大 JSON 传输与宿主调度仍是 A6 发布门禁。若需要调整数据形状，升协议/目录版本，不改写既有操作。

## 6. A3/A4 接入的必需事实与顺序

这些是后续实现要求，**当前纯内存作者没有提供其持久保障**：

- 连接记录、已接受快照/appliedIds、操作规范正文摘要、导入凭据与 outbox 必须来自本机可靠事务/恢复日志；不能从刚同步来的 data.json 或“所有已收到操作”生成已接受事实。本机凭据不进入共享操作正文；A3 需验证设备隔离和外部配置同步情况下的来源。既有缓存不具备该证明时只允许明确首次加入/导入，不调用历史修复接口冒认已应用。
- 单一写队列合并最新设置/UI/布局缓存，不以过期的整份 savedData 回写覆盖其他字段。外部 data.json 变化保持设置草稿和当前编辑，先重读/校验/协调；共享操作集合与本机接受日志是布局因果权威，data.json 是缓存。
- 发布前可靠保存旧快照、原 ID/规范正文、候选与旧凭据到本机 outbox，再登记独立尝试路径并写入，不对已知存在路径覆盖；此条取代旧单路径 create-if-absent 的原子发布要求。该顺序不提供对外部任意写者的原子保证；写后完整目录复核、稳定 ID 重试和已知损坏/缺失暂停是接受前必要条件。规范完整副本已经可见时幂等恢复；自有截断仅在与已登记意图精确核对后有界换路径重试。未曾观察/保留的正文若消失，不能保证报警或恢复。
- D3 普通编辑须先可靠保存本机草稿，再由与接收/保存协调的队列自动发布；当前 stage/pending 正文一旦落盘不得被后续草稿替换。排队不是同步服务调度；输入阻塞或失败须保留已保存草稿/outbox/原 ID，不用无限立即重试放行。**SYNC-UX-A2 修订（2026-11-24）**：首次加入中的普通无歧义情形由用户开启布局同步的授权覆盖（见 §4）；冲突解决、关闭期间草稿恢复仍保留明确确认，不自动采用。关闭同步立即阻止新的共享读写并保留本地工作；再次开启后，关闭期间保存的草稿仍需审阅发布，不因简化首次流程而自动发布。
- 共享写成功但本机提交失败，保留 outbox 和原文件；重启通过精确正文核对恢复同一笔事务，不生成第二个 ID、不删已发布文件。当前笔记/编辑 epoch 改变时重新校验候选，不能因为文件已发布就强行应用过期几何。
- 候选和新接受凭据可靠保存、且应用条件满足后才确认作者并推进会话状态；视图未打开时接受的是已校验的本机布局状态，后续建图按同一身份/几何门禁恢复。补扫、去重和正常读取不触发发布风暴。关闭/回退保留共享历史并先备份，不支持旧版参与双向写入。

### 私有有效配置协调原型（2026-11-08，第六阶段）

### 生命周期与私有容量原型（2026-11-08，第七阶段）

关闭/切换先在设备本地保存独立签名意图，绑定原目标库和起始连接代次，再排空已接收动作、释放会话并完成禁用；重启先处理该意图，不自动打开或发布源/目标，切换目标保持禁用。同库明确重新启用恢复原草稿/outbox；已完成的旧意图不能关闭后来的新启用。新库仍须显式加入，不自动制造空接受事实。

私有数据按正文/文件/事件软暂停与硬拒绝保留恢复余量，不删除历史放行；默认 64 MiB/4096 文件/3968 事件暂停正常 admission，144 MiB/8192 文件/4096 事件为单次创建前的硬保护。数值为待资源/原生验证的工程护栏，不是用户容量承诺或 OS 磁盘配额。只读兼容输出及分片回查包不自动写 data.json、不携带设备密钥、不作为接受账本导入；详细接口/范围见 [SYNC_A3_LIFECYCLE_BUDGET](SYNC_A3_LIFECYCLE_BUDGET.md)。正式禁用后本地工作/兼容落盘、明确恢复导入及近限额资源/原生验证仍待后续。
