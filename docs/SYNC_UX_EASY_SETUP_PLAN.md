# Knowledge Map 同步易用性改造实施计划

> **执行方式：**下一位 coding agent 先读取项目 `AGENTS.md`、`README.md`、`TODO.md`，以当前源码和最新任务记录为准。
>
> **Goal：**首次使用只需点击一次“开启布局同步”；普通情况下自动准备默认布局、连接共享图谱、保存和接收修改。
>
> **Architecture：**保留现有操作历史、私有账本、布局校验和恢复机制，新增自动初始化与连接编排层，重做同步设置界面。
>
> **Tech Stack：**现有 JavaScript/MJS、Obsidian API、IndexedDB、Node 合成及磁盘测试、现有浏览器测试设施；不新增运行时依赖。
>
> **设计依据：**本计划第 1–2 节，来自本聊天已确认的产品方向。

## 1. 已确定的目标与边界

用户已确认：

- 首次主动开启一次同步，此后正常使用自动运行。
- 移除“先手动移动一个圆才能开始同步”的要求。
- 自动处理创建、发现、连接和普通首次加入，不要求用户理解共享 ID。
- 设置页精简，按实际状态引导操作。
- 保留现有历史存储方案，本次不改为单个可覆盖的图谱文件。

成功后的全新使用流程：

1. 两端安装并启用插件。
2. 用户在两端分别开启“布局同步”；没有图谱时自动打开并构建当前库图谱。
3. 插件自动准备默认图谱及共享初始化资料。
4. 现有同步工具传输 `Knowledge Map Sync` 文件夹。
5. 插件自动连接并接收后续布局，用户无须新建、查找、选择 ID 或手动确认空布局。

本次只同步布局结果。建图范围、设置、视角和界面状态继续留在本机。首次引导应明确说明：两端需使用相同建图范围，外部同步工具需包含上述文件夹。

验证范围沿用 **Windows ↔ iPadOS + 坚果云**。不增加云服务账号设置，不控制坚果云队列，不承诺任意同步工具均已验证。

## 2. 必须遵守的行为与技术契约

### 默认布局与初始化

- 没有手动调整时，默认布局用现有 schema3 的**空覆盖状态**表示，继续使用自动布局；不把全部自动坐标伪装成手动调整。
- 首次成功构图后即可使用该状态，不依赖一次拖动。
- 同步未开启时，不创建共享文件、不自动加入共享历史。
- 空布局也必须能生成可传输、可发现的初始化资料。
- **不发布 reset、清空操作或虚假编辑来充当初始化标记。**

### 两端同时首次开启

采用同一 vault 文件夹内的固定默认命名空间，避免两端离线首次开启时分别生成随机图谱 ID：

- 默认 ID 为 `SHA-256("KM-SYNC-DEFAULT-LAYOUT-1")` 的前 32 位小写十六进制，即 `71e90242bea19488f2a16c60f78fcabc`。
- 这个 ID 只标识各库内的默认图谱；不同 vault 目录之间不扫描、不合并。设备身份、密钥、操作 ID 和私有账本继续独立。
- 高级功能中新建其他图谱仍使用随机 ID。

新增独立初始化目录：

`Knowledge Map Sync/bootstrap-v1/<default-id>/<sha256>.<attempt-id>.json`

初始化正文固定为版本、类型、传输和默认 ID，不包含设备身份、笔记、坐标或时间戳：

```json
{
  "version": 1,
  "kind": "default-layout",
  "transport": "attempts-v1",
  "vault": "71e90242bea19488f2a16c60f78fcabc"
}
```

要求：

- 使用统一规范化编码和正文摘要；attempt ID 使用现有随机 ID 规则。
- 文件不可变，采用独立尝试路径及写后读回校验，不引入可覆盖的权威 manifest。
- 两端生成的合法同正文记录按一个初始化事实处理，不构成布局冲突。
- 初始化记录只允许发现默认图谱，**不能证明布局已经接受或另一端已经收到**。
- 完整扫描、大小与数量保护、残片及摘要校验沿用现有保护原则；未知版本或损坏输入暂停自动流程，不能当作“没有图谱”重新初始化。
- 现有布局操作继续使用 `attempts-v1`、protocol2、layoutSchema3，不增加布局操作类型。

这有意调整现有协议文档中“所有图谱 ID 随机”“空布局不可发现”“首次加入一律手动确认”的规定。实施时必须更新对应条款并保留变更说明。

### 自动连接与已有布局

按以下顺序处理：

- **已有本机连接：**沿用原 ID、传输、加入进度和启用状态；升级本身不触发重新加入、切换或发布。
- **首次开启，只有一份有效的可写共享图谱：**自动选择该图谱。
- **没有共享图谱：**准备固定默认图谱；写入初始化记录后重新扫描，再连接。
- **发现多份图谱：**展示一次易读的图谱选择界面，ID 放详情；不按时间或目录顺序选胜者。
- **只有旧 v2 只读历史：**说明只读状态并提供现有审阅/恢复路径，不自动改为可写历史。
- **空本机布局：**在用户开启同步的授权下，完成备份及完整校验后自动采用共享布局；共享布局为空也可加入。
- **本机已有手动布局、共享历史为空：**完整备份及严格校验后，自动导入一次本机布局。
- **两边布局语义相同：**备份、核验后自动采用共享布局，不重复发布。
- **两边已有不同布局：**展示本机与共享预览，由用户决定；沿用现有保留分支和冲突解决机制，不直接覆盖任一方。
- **本机旧布局存在校验问题：**沿用现有“当前可用布局”审阅及归档保护，不自动丢弃不可用组。
- **连接后才收到其他命名空间：**保留当前连接和工作，提示发现其他图谱，提供审阅入口；不静默切换或跨命名空间合并。

所有自动加入仍经过现有备份、指纹复核、图谱兼容性和写入门禁，不能用 UI 层直接改接受状态。

### 开关、恢复与事件

- 关闭同步立即阻止新的共享读写，保留本地工作。
- 再次开启后，关闭期间保存的草稿仍需审阅发布，不能因简化首次流程而自动发布。
- 私有身份、账本或进度缺失时进入恢复流程，不能当作新安装生成替代身份。
- 自动流程由开启、插件重开、图谱就绪、文件事件、窗口恢复及编辑结束唤醒；事件合并处理，不使用持续高频扫描。
- 编辑中、图谱过期、关闭中或多视图存在歧义时等待，不强行应用。
- 每个阶段可重入、可恢复；重复点击、重复文件事件和重开不得重复导入或重新分配目标。
- 自动编排复用宿主串行事务，避免在已入队事务中再次调用并等待同一队列的公开方法，造成死锁。

## 3. 界面与引导设计

普通设置页只保留：

- **“布局同步”开关**：首次操作显示“开启布局同步”。
- **当前状态及一句说明**。
- **至多一个与当前问题对应的主要操作**。
- 默认折叠的 **“高级与恢复”**。

状态文案应准确区分：

- 未开启：“在设备间共享图谱布局。”
- 准备中：“正在准备图谱……”
- 本机就绪：“已准备共享资料。请让同步工具传输 Knowledge Map Sync 文件夹。”
- 本机无待办：“本机布局已保存，当前没有待处理修改。”
- 待发布：“修改已保存在本机，正在准备共享文件。”
- 已写出：“共享文件已写入，传输由你的同步工具完成。”
- 等待笔记或前驱：“正在等待对应笔记或较早的布局记录。”
- 需要选择：“发现多份图谱”或“这台设备与共享布局不同”。
- 已关闭：“同步已关闭，本地工作保留。”
- 出错或恢复：“同步已暂停”，附用户可理解的原因与下一步。

不得显示未经证实的“两端已同步完成”或“已连接到另一台设备”。

高级区域保留现有能力：检查共享布局、新建/切换其他图谱、共享 ID 与诊断、完整恢复备份、兼容导出、轮换及异常恢复。冲突和待发布草稿出现时，相关入口提升到普通区域。

使用 Obsidian 原生主题变量、开关、折叠区和按钮；支持中英文、键盘、读屏、窄屏和触屏。不改变现有图谱画布风格与交互。

先用现有浏览器 fixture 提供可点击草图，覆盖未开启、准备完成、正常使用和冲突四种状态，交用户确认视觉与文案。核心逻辑与测试可同时推进，正式 UI 接入以该确认结果为准。

## 5. 测试、验收与交接标准

新增合成和磁盘测试，注册进入现有测试入口。至少覆盖以下场景：

- **全新双端，无拖动：**开启、初始化、互传、重开，目标一致、无虚假布局操作。
- **两端离线同时开启：**交换文件后仍为同一默认图谱，重复初始化记录不产生冲突。
- **首次真实编辑：**A→B、B→A 均能接收，重开保留。
- **同时编辑：**不同独立范围按原协议处理；同组竞争保留双方并要求审阅。
- **旧连接：**升级不更换 ID、不重新导入、不改变原启用状态。
- **已有布局：**本机独有、共享独有、相同、不同、旧布局不可用及当前可用投影分别验证。
- **迟到与乱序：**笔记未齐、前驱未齐、旧命名空间迟到、多个目标和损坏输入均有明确状态。
- **关闭再开启：**关闭无共享 I/O，草稿保留，重新开启不自动发布关闭期间工作。
- **中断：**授权落盘、初始化写入、连接选择、备份、加入及首次编辑发布各阶段退出后可恢复，无重复导入。
- **界面：**中英文、明暗主题、窄屏、键盘和触屏；正常页面无按钮堆叠，异常操作可达。
- **已有恢复能力：**完整备份、兼容导出、轮换、私有存储缺失及容量保护不退化。

1. 新增纯逻辑检查与 `npm test`。

3. 浏览器交互及布局检查。
4. Windows Obsidian 两个独立库测试。
5. Windows ↔ iPadOS + 坚果云独立库测试。
