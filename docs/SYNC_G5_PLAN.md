# G5 损坏与失败恢复实施计划

> 执行：使用 executing-plans 逐项实施；每项按失败复现→最小修改→复核推进。现有工作区保留未提交同步实现，故障注入仅在新建合成库和专用profile；不对旧HEAD新建缺少当前实现的checkout。

**目标：** 统一候选真实图谱/设置入口发现故障后保留原件和本机工作，可解释地暂停，恢复须重新审阅，重复发布保持同一逻辑ID。

**依据：** SYNC_0.0.16_FORMAL_REVIEW.md 第9节G5。D1有条件文件传输保证、D2 Windows↔iPadOS+Nutstore首批范围、D3普通保存自动排队不变。版本仍0.0.15独立候选；原G4的25操作现场、FB2双PC验收库、日常库不动，无commit/push/发布。

**架构：** 复用真实graph-core store、UnifiedHost、session/journal、attempt history和现有审阅，不另写发布/解决协议。外部共享原件不能由修复测试或恢复按钮悄悄覆盖/删除；可通过恢复原始正确字节或将异常输入移出共享操作目录后，重新审阅当前库存。持久同ID隔离不能靠删除坏文件或重开自动解除。若当前接口无法审阅修复后的输入，补受签名日志保护的显式恢复确认，保留原隔离证据。

**实现文件：** scripts/sync_unified_g5_check.mjs（真实图谱/宿主故障集成）、scripts/sync-g4-helpers.mjs（仅必要故障注入扩展）、src/sync/persistence-prototype.mjs（仅证据确认的恢复缺口）、src/sync/obsidian-unified-host.mjs与obsidian-sync-settings.mjs（恢复审阅门禁/正常按钮）、src/i18n.sync.js；浏览器/专用Windows原生驱动及合成交付指南按验证需要新增。现有disk脚本用于进程退出证据，不用其直接confirmed接口代替用户UI。

## 复核重点

- 完整但同ID不同正文、未知名或任意损坏不能被“再写一份”掩盖；原件/隔离证据保持。
- 已接受文件丢失时接受布局不回退或清空，恢复原字节后才重新检查；从未观察的外部删除不作发现保证。
- 写出后本机提交失败/epoch或源变化，原intent与ID不重造；过期审阅不能确认，取消不写。
- 关闭/隐藏/编辑/本地保存未完成时不应用远端、不静默授权恢复；私有存储失败不能被显示为已完成。
- 错误提示/导出/恢复按钮必须在真实页面可到达；不得据内核通过声称iPad体验验收通过。
