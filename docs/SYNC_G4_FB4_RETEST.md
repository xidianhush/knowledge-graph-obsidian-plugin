# G4-FB4 更新与原现场续验

2026-11-15。沿用现有Knowledge Map G4 PC / Knowledge Map G4 iPad和远端 `/KM-G4-e9d8fed3/`。候选名称仍为Knowledge Map Sync Candidate，版本仍显示0.0.15。

## 一：两端更新运行文件

1. 暂停自动传输和编辑，完全退出PC/iPad的Obsidian。
2. 解压更新ZIP，将`knowledge-map-sync-unified`中的 **main.js、manifest.json、styles.css** 替换到各自原G4库的 `.obsidian/plugins/knowledge-map-sync-unified/`。只替换这三个文件；保留data.json、本机存储、笔记和全部共享历史。
3. iPad沿用之前成功更新原测试库的方法访问隐藏.obsidian：在支持显示隐藏文件的文件管理器中打开实际正在使用的Knowledge Map G4 iPad库，进入上述插件目录，只替换三个运行文件。若不能访问目标目录，请停下提供截图；不要用新空库替代原现场，也不要同步整份.obsidian。
4. 两端重新打开原库并建图，各保留一个图谱。先不改笔记、不传输。原竞争仍需要明确选择，更新本身不会删除旧分支。两端都更新后再继续；混用旧候选仍可能产生重复结构记录。

## 二：只在PC恢复当前竞争

1. PC点「审阅布局冲突」。应显示当前竞争版本；含已删除Fifth的旧版本保留预览，并标示“此版本与当前笔记或标题结构不匹配，暂不能采用；原记录仍保留”，该卡片不可选择。
2. 先点「取消」，核对PC图谱未改变，导出 **G4修复-取消-PC.json**。
3. 重新审阅，选与当前PC一致、不含Fifth的可用卡片，再点窗口底部的最终确认。导出 **G4修复-解决-PC.json**。正常会新增一条解决记录，保留旧20条原件。
4. PC坚果云同步完成后，iPad再同步；iPad点「检查共享布局」。两端应采用PC所选布局，均无待审冲突。无需在iPad另作决定。

若没有可用卡片、预览未弹出、出现新草稿/损坏/缺失/身份/容量提示，或两端仍不同，导出当前状态和截图后停下；不删除文件、不重建共享布局或重新导入。

## 三：正常标题往返

1. 只在PC的Moved/C.md末尾新增一级标题Fifth和一行正文，等待图谱更新；PC同步→iPad同步，检查两端标题和局部布局一致。
2. 只在PC删除刚新增的Fifth及正文，等待更新；PC同步→iPad同步，再检查。无需控制服务内部文件到达顺序；同一前驱和完整内容相同的自动结构记录应合为同一逻辑操作，物理尝试文件可以不同。
3. 两端导出 **G4修复-结构往返-PC.json / G4修复-结构往返-iPad.json**。若出现冲突，先停止并导出；不要反复增加/删除来消除提示。

## 四：最终重开与回交

两端完全退出并重开，建图、检查，导出 **G4修复-最终-PC.json / G4修复-最终-iPad.json**。

集中回交以上 **6份JSON**，以及两端最终图谱/同步设置截图。反馈取消是否不改变布局、不可用版本提示是否清楚、正常新增/删除是否一致。

本次技术预检使用合成库、Windows原生profile与本地复制，不代替本轮iPad/Nutstore验收。FB2跨库连接锁仍是独立待修项；测试时PC只打开这一个候选测试库。原黑条现象尚未定位，若影响操作请附截图。未正式发布0.0.16。
