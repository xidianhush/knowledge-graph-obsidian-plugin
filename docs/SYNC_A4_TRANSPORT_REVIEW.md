## 建议与决策点

建议先把独立尝试文件接入一个**显式启用的独立候选**。在正常运行的 Knowledge Map 写入方之间，同一逻辑操作的每次写入使用独立路径，收端按正文摘要和因果关系核验。任意外部写者抢占精确路径时，底层仍可能覆盖。如果被覆盖的正文从未被观察或保留，事后扫描无法还原它。摘要只校验当前读到的字节，无法证明写入历史。

本轮产品决定覆盖配对的独立测试库。若正式版要求任意外部写者下的原子不覆盖，现有跨端原语筛选仍不足以支持双向发布。

## 候选传输规则

### 独立目录与持久意图

1. 建议目录为 `Knowledge Map Sync/attempts-v1/<vault-id>/ops/`，文件名为 `<op-id>.<sha256>.<attempt-id>.json`。正文沿用现有 `protocol: 2` 和 `layoutSchema: 3`。尝试 ID 由 Web Crypto 生成 128 位随机数，已知占用就重新取值，设有限次上限。连接、首次加入预览和私有日志均绑定逻辑库与传输版本。
2. 先可靠保存旧快照、原操作 ID、规范正文和候选摘要，再记下本次尝试路径，然后写共享文件。一次写入失败或结果不明时，重开先扫描。完整正文已在有效路径可见时恢复同一逻辑操作；需要补写时，保持原 ID 和正文并分配新路径，即使旧路径暂时不可见。进入写入意图后，取消动作不得删除共享记录。
3. 只有目录核验通过、此前接受的正文仍可核对、待发布操作未隔离且满足布局与编辑代次门禁，才能持久提交新的本机接受凭据。补扫先校验扫描输入是否变化，再使用结果；它只代表采样时可见的目录。客户端同步完成或对端确认须另有证据，不能从本机写入成功推断。

### 截断、乱序与冲突

1. 有效路径上的文件必须匹配操作 ID、逻辑库和 SHA-256，并通过规范 UTF-8 正文及 schema3 校验。相同正文的完整尝试逻辑去重。后继缺前驱时等待。有效路径下同 ID 的不同完整正文全部保留，该 ID 隔离，后继等待。
2. 截断文件只有在**同 ID、同预期摘要**的完整正文存在，且原始字节是其精确前缀时才解除阻塞。接收端保留截断原件。发送端可对私有日志中登记的本机尝试执行有界重试，即使该截断正在阻塞扫描。前提是与私有 outbox 精确核对，且没有其他未解释的阻塞或同 ID 冲突。任意损坏字节或另一份正文的残片继续阻塞。
3. 对选中目录内的异名文件先限量读字节，记录实际相对路径、大小和 SHA-256。能验证为同库合法操作的正文参与冲突识别，异名文件本身只作为证据。未知命名或无法识别的正文保留原件，并暂停共享应用与发布。下一版候选必须证明晚到冲突能冻结已有接受基线，且一份曾见冲突文件随后消失时，仍需显式审阅才能恢复。审阅前保留已接受布局和本机草稿。
4. 所有物理文件都占用扫描配额，包括重复、残片和异名副本。沿用 1024 个物理文件、单文件 2 MiB、总正文 32 MiB 作为候选上限，先检查大小再读并复核实际读入字节。预算耗尽时暂停并保留可导出的本机状态和原件。由实测确定重试上限及容量提示阈值。自动清理共享记录不在本轮候选范围。

### 旧目录与回退

保留 `v2/<vault-id>/ops` 的现有只读入口。旧目录、探针目录和候选目录分别枚举，用户显式选择。候选首轮使用新逻辑库和新目录。若需带入旧布局，先备份、核对旧历史和现有 outbox，由用户显式选择一份已验证的布局快照作为新库根操作。存在未解决冲突或未完成发布时先保留并审阅，避免把未提交事实带入。新库根操作携带的是布局快照，旧历史与旧凭据在原位置保留。关闭候选后回到原有本机布局/只读恢复入口。

## 候选与发布门禁

- **A4 接入检查**。同一隔离候选覆盖写入意图落盘前后、截断写入后、完整写入后和本机接受提交前的进程退出。重开核对同一 ID 和正文、路径换新、原件保留、无重复接受。覆盖单文件回读成功但目录已有同 ID 冲突、上次接受的正文消失、空目录与不可读目录、未知名称和内容、触顶，以及写入期间图谱或草稿变化。
- **A6 真机检查**。Windows 与 iPadOS 各自在同一基线离线编辑，验证同组冲突与不同组独立编辑，反转到达顺序，覆盖重试、切回前台、完全退出重开、真实布局编辑和零接收写回。隔离目录另做一次有控制的同物理路径竞争，保存 Nutstore 的实际处理结果。若生成副本，记录两端路径和正文摘要；若替换或合并，记录前后字节及候选如何暂停。近限额样本须复核两端资源开销和可恢复的触顶状态。
- **A5 / 发布复核**。用户验收待同步、等待、冲突与容量提示，明确区分本机写入、可接受布局和对端确认。A4/A6 技术门禁通过后，再评审正式支持范围、兼容和原子不覆盖风险。候选确认只授权在独立库验证。

首个候选采用每笔操作最多登记 4 条尝试路径。实际测试范围和未覆盖的门禁见[实施结果](SYNC_0.0.16_RESULT.md)。
