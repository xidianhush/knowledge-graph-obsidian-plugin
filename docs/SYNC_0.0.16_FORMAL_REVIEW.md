## 3. D1：正式传输保证拟如何调整

### 3.1 仍然必须做到的事

1. 每笔操作先保存本机旧状态、规范正文、稳定逻辑 ID 和持久意图，再写共享文件。发布重试不换逻辑 ID，不删已发布历史假装取消。
2. 每次新写入使用独立路径。当前目录为 `Knowledge Map Sync/attempts-v1/<vault-id>/ops/`，文件名为 `<op-id>.<sha256>.<attempt-id>.json`；最多登记四条尝试路径。分配失败/次数耗尽保留意图并提示，不能无限制造文件。
3. 发布和接收均核验完整选中目录，不能只回读自己刚写的单文件。接受本机操作之前要检查旧接受正文仍存在且一致，且没有其他未解释的阻塞。UI/图谱 epoch、草稿、保存和拖动门禁保持。
4. 已保存的接受记录来自本机受校验日志；“收到文件”不变成已应用前驱。首次导入为独立根；同组并发不按时间或 revision 选赢家，明确解决产生引用双方分支的新操作。
5. 采用共享和读取/补扫本身不发布；恢复/备份不冒充已接受账本。SHA-256 校验内容，不能证明作者身份、传输完成或远端历史从未被修改。

### 3.2 明确不承诺的事

- **不承诺任意外部写者下的原子不覆盖。** 随机路径减少合作写入方碰撞，不是文件系统排他创建。当前 `createAttemptHistory.write()` 的 stat 后 write 存在外部竞争窗口。
- 已知路径被改成不匹配正文时可检测并暂停；曾接受记录消失时可与本机日志对照。若一笔记录在任何保留它的设备之外被删除、或在接收端首次观察前消失，接收端可能根本不知道它存在，不能承诺一定报警或一定恢复。
- 无法还原的字节不能靠哈希推导。恢复优先寻找仍保留的原始正文、发送端 outbox 或已有备份；都不存在时只能说明缺口，不能静默生成“相同历史”。
- 本机写入并接受不等于坚果云已上传、另一端已下载或已应用；没有确认协议或用户报告时，不显示“所有设备已同步”。

## 5. 正文、目录与本机身份的兼容方案

建议保留 `protocol:2`、`layoutSchema:3` 的操作语义，采用 **attempts-v1 传输目录**。这是传输契约变化，不把正文协议数字自动当作跨目录兼容许可。

- 新正式连接记录显式绑定逻辑 vault ID 与传输版本；新建/发现/多个命名空间选择使用真实用户入口，不依赖 OnboardEmpty/Resolve 标记。测试按套件隔离身份不能直接当正式设备身份迁移方案。
- `v2/<id>/ops`、`attempts-v1/<id>/ops` 分别列举和核验；不把两个目录的记录自动拼起来，也不自动扫描其他库当作已选择历史。旧 v2 保留只读/明确恢复入口；是否从旧验证布局建立新逻辑库根，需要备份、outbox/冲突检查与用户明确选择。
- 空本机采用共享不发 reset。两个旧布局导入仍产生两根；已验收的 preview/cancel/retry 语义保持。目录发现/双端同时新建、正式身份缺失与复制配置、切换恢复尚须统一宿主验证。
- attempts 读取要求规范 UTF-8 正文与文件名摘要对应；相同规范正文多次尝试逻辑去重。异名副本、未知名称不能忽略；合法异名同 ID 正文参与冲突识别，未知/损坏原件保留并暂停。
- 已见同 ID 两正文的隔离事实持久化；删掉其中一份文件不自动解除隔离。当前没有面向用户的完整隔离恢复 UI，不能把普通同组“择一布局”当同 ID 损坏修复工具。
- 设备身份、私有密钥、接受日志、进度锚与草稿在设备本地 App 存储/IndexedDB，不随 data.json 复制就被信任；它们也不是“同步目录备份即可恢复”的数据。丢失时先阻塞和保留进度线索，再明确重新加入/恢复草稿，不能新建假身份冒认旧接受事实。

若设备密钥或唯一私有副本已丢失，且无其他有效副本/导出，未发布草稿、本地设置或 outbox 可能无法恢复。重新加入只能建立新的本机接受状态，不能凭空重建这些字节。

D1 确认后已修订旧契约的第 1 节目录/发现、第 2 节规范字节要求、第 5 节物理文件预算和第 6 节发布原语，并明确跨目录/恢复规则。保留 F1/F2/F3 为历史反例，原“任意外部写者下原子不覆盖是必要发布条件”由 D1 有条件保证取代；这不是原语缺陷已修复或发布门禁已全部通过。

## 6. 失败、等待与容量的可用性要求

对用户至少区分：本机已保存、等待写共享文件、已写本机共享目录、等待前驱/笔记、同组冲突待选择、损坏/缺失/隔离待恢复、容量或存储失败暂停。状态要有具体原因和下一步，不能用一种“同步成功/失败”覆盖所有阶段；不虚构服务实时进度或对端 ACK。

### 共享预算

当前保护线为 **1024 个物理文件（含重复/残片/副本）**、单文件 2 MiB、总正文 32 MiB。正文核心另有 parents/changes/关联组/坐标/JSON 护栏。四次尝试上限不等于最多支持 1024 次用户编辑，复制/重试也会占配额。

已有真机 near 样本为 1023 文件、33,521,664 字节，逻辑去重**一笔**；恰好边界可读，+1 文件/字节拒绝，移出探针新增项后恢复。它证明扫描护栏，不是 1024 笔不同布局操作、多组图谱集成或 iPad 内存支持承诺。缺少的单独 iPad 触顶重开附件有后继日志检查证据，不因本稿重做千文件试验。[容量证据](SYNC_0.0.16_RESULT.md#sync-a6-共享文件近限额与触顶恢复双端回执2026-11-13)

### 私有预算与本地保存

源码当前软暂停为 64 MiB / 4096 文件 / 3968 日志事件，硬创建上限为 144 MiB / 8192 文件 / 4096 事件；任一项可先触发，恢复调用仍受硬线约束。这是 App 私有存储保护，不是 OS 剩余空间。共享触顶不等于私有触顶，反之亦然。

关闭同步后的同库本地工作原型已有证据，但私有软暂停后普通 admission（包括 local-only）也可能被拒绝；**不能承诺超限后还能无限保存新编辑**。必须保留已经可靠保存的数据，无法持久化的新修改明确显示未保存/暂停，不得显示成功；统一宿主须验证必要恢复操作在余量内可执行。

### 发布前必须补齐的恢复出口

建议首版不自动 GC、删除 tombstone 或压缩旧历史。但这意味着容量有限，不能只给一个“已满”提示就发布。须提供并验证：

1. 可读地显示受限项，允许导出经过校验的已接受布局、原始备份和单独待处理草稿/待发布状态；不是把整份私有账本或密钥交给同步目录。
2. 对有完整快照、无未解决冲突/未完成发布的情况，明确备份后可创建**新逻辑库**，从所选验证快照作为根重新开始；旧历史原位保留。该轮换流程是建议的最小恢复实现，**目前没有可交付正式 UI 或端到端验收**。
3. 有冲突或 pending 时不能静默压成一个根。先恢复/解决或单独保全每个分支；不能拿删除/移出真实历史来仿照容量探针“恢复”。无法保全时暂停轮换。
4. 所有参与设备明确切换/重新加入；旧离线设备回来仍可能写旧命名空间，它不会自动并入新库。保留旧现场并明确提示，必要时将其旧布局按首次导入流程审阅，不宣称新旧历史已无损自动合并。

若这套有限容量与手动轮换体验无法接受，应在发布前另评历史压缩/GC；本稿不偷偷引入“已实现自动归档”。

坚果云首传曾限流停在 55.71% 约二十分钟，后续完整到达已补证；不把续传完成等同限流问题已修好。通过本机合并扫描与有限重试减少额外工作，服务退避仍由服务处理，不承诺传输时长或 iOS 后台常驻。

## 7. 关闭、备份与回退到 0.0.15

建议“关闭同步”与“卸载/降级”分开：关闭先持久记录意图、排空当前动作、关闭接收/共享写入，保留共享历史、原 ID/outbox 和本地草稿；再次启用需重新核对而不是自动发布关闭期间的编辑。

降级前先停止共享接收/发布并按生命周期排空、释放旧会话，再在受控只读或 disabled local-only 会话中选择并导出兼容数据；导出核验完成后关闭导出会话，再卸载/降级。不能在 bundle 已释放后直接调用依赖打开会话的现有导出接口；该组合流程仍须 G7 实现验证。**不能直接拿旧 data.json 备份当作最新布局**：候选中的最新接受状态/草稿可能只在私有日志，旧 JSON 仍是首次加入前的布局。用户需要明确选定已验证布局；有冲突或 pending 时，先保全各版本并说明哪些尚未发布，不能假装它们已经撤销。

生成供 0.0.15 使用的兼容 JSON 后，在独立库验证原设置/UI/未知字段和所选 schema3 布局可读、重开保持；通过后才形成正式备份/回退指南。私有日志/锚不是可直接导入旧版的文件，卸载或清除 App 存储可能使其不可用，必须先保留独立备份。已有兼容导出/草稿恢复原型不能替代这一实际旧版回退门禁。

回退的设备不再参与该新逻辑库的双向写入；不支持 0.0.15 与 0.0.16 同时编辑同一同步历史。保留旧共享目录，升级回来仍需按现有接受/身份/结构门禁重核，不因旧版曾读过布局就信任其后写入的 data.json。

## 8. 数据与信任边界

共享正文包含库内相对路径、标题/结构证据与布局坐标，可能暴露笔记组织和标题；它不是全文同步功能，但不能宣传为无任何笔记信息。共享正文不应带原配置、私有密钥、设备绝对路径或凭据。完整原配置备份会保留未知字段，不能笼统声称所有备份均无敏感数据。

启用后第三方同步工具会把选定文件送至用户配置的服务，插件本身不持有其登录凭据。用户需信任同步目录的写入者；共享哈希不提供身份认证或加密，能写该目录者可构造合法新操作。私有签名用于本机恢复核验，不等于共享操作有签名或端到端加密。
