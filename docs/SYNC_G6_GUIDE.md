# G6 新合成库：有限容量与受控轮换

仅用于此全新测试包；不要在原G4/G5/FB2或日常库操作。候选仍0.0.15、ID knowledge-map-sync-unified，不是正式升级。新远端：`{{REMOTE}}`，原逻辑ID：`{{VAULT}}`。

PC包预置两组、1024笔**不同**操作（不是一笔的千份副本）。原共享目录恰达物理数量保护线，仍应能读取。iPad包不含共享原件，由全新坚果云目录传输。此包用于共享数量与轮换；私有字节/事件/文件容量、iPad内存/FPS不因它通过而自动通过。

## 1. 两端基线

1. 解压成两个新库，使用独立候选插件。按既有坚果云方法，仅将新PC/iPad库配到上述全新远端，不复用旧远端。
2. PC共享文件完整上传/iPad完整下载后，两端先运行“从当前库构建知识图谱”，等图谱显示，再开同步设置。
3. 两端点“查找共享布局”，选原ID，审阅并确认；再点“审阅并加入”，明确选择已有共享布局。不要“新建共享布局”或导入本地布局。
4. 两端“导出同步状态”，回交报告和图谱截图，确认布局相同。报告应accepted有1024不同ID。若受限/未完成，保留现场和报告，停止后续步骤。

## 2. 备份与触顶工作

1. 两端设置中“本库内备份目录”保持 `Knowledge Map Backups`，点“导出恢复备份”，等待显示“已完整核验”。完整备份含原始备份、接受操作、独立草稿/pending及最后写入的manifest。它是私有资料，请整目录另复制到库外；不要只保留状态报告。
2. **仅PC**正常拖动一个标题并结束调整。共享文件已满，预期暂停，不出现成功同步的误导。导出状态报告，说明是否仍显示拖动结果。
3. PC再导出恢复备份。**正常提前容量门禁会只保留草稿，报告pending=null，也没有“放弃待发布”按钮；这是预期行为，可直接进入第3组。** 只有报告确实存在pending且未分配尝试路径时，才点“审阅放弃未写入的待发布”，先取消一次（原待办应保持），再审阅确认。此动作只放弃发布意图，原ID/正文仍保存在历史及备份，草稿保留。
4. 如果提示有写入路径、正文已可见、输入不完整或其他原因，**不要删共享历史、不要改ID、不要强行轮换**；保留报告回交。此分支不能用此按钮绕过。
5. 如果执行过放弃，再导出一份新恢复备份和状态报告，不使用放弃前的旧备份轮换。没有pending时，使用第3步刚完成的草稿备份即可。

## 3. 明确选择草稿并轮换

1. PC选择“将已保存但未发布的草稿明确导入为新根”，点“审阅新逻辑库轮换”。核对原/新ID、备份目录与预览；先取消一次，原ID、草稿和布局应保持。
2. 再审阅并确认。新库应只有一笔根操作，布局是刚才草稿；旧目录的1024份原件仍在。记录**新ID**，导出状态报告。不要把此动作称为旧库草稿曾成功发布。
3. PC完全退出Obsidian再重开，先显示图谱后进设置。新ID、新根ID和布局保持，导出报告。
4. 若中断，设置会显示“审阅未完成的轮换”，只能基于原备份继续同一次目标/root ID。新连接选择前，可明确“取消尚未切换的轮换”，保留旧连接当前启停状态后重新检查/备份。新连接已切换时不能用取消来撤回共享根。

## 4. 旧离线端返回与明确切换

1. PC轮换期间让iPad保持原ID离线；在iPad旧库做一次不同拖动，再联网完整传输。原目录已满，因此这笔工作可能仍暂停/待发布，须如实记录。
2. PC检查：新库不自动并入iPad旧ID的工作，新ID与布局保持。两端分别导出恢复备份和状态报告，先保全iPad旧工作。
3. iPad关闭同步、查找新ID并审阅选择。若显示“未完整扫描，选择后单独核验该库”，这是旧/新总库存超全局发现预算的受限列表；选择新ID时仍会完整核验目标，不能据此推定所有库正常。
4. iPad“审阅并加入”明确采用新共享布局；不要导入iPad旧布局覆盖新根。两端检查、完全退出重开，再回交报告与截图；新ID/操作正文/groups/structures应一致。

## 回交与范围

至少回交：两端基线，PC触顶/放弃后/轮换后/重开后，iPad旧端返回/明确加入后/最终重开后报告；两端最终图谱截图；备份完整目录的文件数/总字节及导出耗时、冷开耗时和实际操作感受。私有备份不发公开issue。报告中没有FPS/heap就不推算。若任一步受阻，只回交该步报告/现象，保留现场。

本轮不能代替真实OS断盘、iPad内存上限、所有服务传输时长或G7旧版本回退验收。体验结论由你确认。
