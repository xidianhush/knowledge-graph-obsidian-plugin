## 持久状态

私有根目录由宿主注入并独立于共享目录，原型布局如下：

- `blobs/<sha256>.json`：规范化操作正文和 schema3 快照，按内容去重；旧接受快照即每笔事务的可靠 before-image，保留原文件。
- `intents/<operation-id>.json`：该笔操作的 vault/installation、旧日志头、正文/旧快照/新候选摘要、下一组 appliedIds；不把大快照重复嵌进日志。
- `events/<12位本机序号>.json`：不可变 init → stage → publish → accept/cancel 事件，previous 指向上条规范正文 SHA-256；序号只用于本机恢复，不参与跨端胜负。

SHA-256 用 Web Crypto，JSON 沿用 A2 有界规范化，拒绝非 JSON/getter/超预算；操作 2 MiB、快照 8 MiB，私有元数据 256 KiB，日志最多 4096 事件、intent 最多 1024。摘要校验用于发现损坏/不一致，不是签名或针对有权限重写整个私有目录的攻击者的身份认证。

私有 blob/事件/intent 规范正文必须精确一致；改写、部分 JSON、链断裂、缺文件、缺序号均阻止继续写入，不回落到旧的空接受状态。未引用 blob 和中断临时文件保留作诊断，未提供自动清理/归档；私有磁盘占用与长历史回放成本还需测量，不能宣称无限容量。

已完成 intent 安装、但 stage 日志尚未写出的进程中断，可在重开时找到唯一孤立 intent：仅当其旧日志头与当前头一致、备份和投影都匹配，才补记 stage。多个或过期孤立 intent 停止并要求审阅，不能猜“最新”文件。中断发生在 intent 本身完成安装之前，不算已可靠暂存；保留其临时文件/blob，调用方仍须保留未确认的本机编辑。统一编辑草稿保存仍待后续接入。

## 会话顺序与边界

`open()` 取得私有写入排他权，验证完整事件链及引用文件，重建旧接受快照和 pending。它不从共享目录或 data.json 推定 appliedIds，也不因为当前笔记已变化就抹掉旧凭据。

`initialize()` 只接受明确空状态或调用方已明确验证的采用结果：appliedIds 必须精确对应给定记录，当前隔离模型候选与快照一致；采用的每条共享规范正文也必须和摘要一致。初始化不是从任意共享文件自动承认应用；非空本机旧布局首次导入还没接入本模块。

`stage()` 验证 A2 作者的 proposal/appliedIds/parents 与旧接受状态一致，通过当前模型完整候选门禁，可靠保存操作和候选 blob，再安装 intent 并记 stage。每笔事务都带旧接受快照备份；调用者提交后修改原对象不影响队列里已捕获的内容。此时共享文件尚未创建，接受状态也没提前推进。

`publish()` 再验证当前模型/编辑 epoch，并逐一核对已接受前驱的共享规范文件。前驱暂缺时保留 pending；正文被改写/部分 JSON 时停止，不能悄悄承认旧父记录。

发布前先可靠写一条 publish 事件，表示“发布可能已开始”；再 create-if-absent 写唯一共享文件并核对完整规范正文。同名同值幂等保留原格式，同名不同值或损坏文件不覆盖。已记录 publish 后，即使共享文件尚不可见，也拒绝当作未发布取消；重开继续原 ID/正文。

最后安装 accept 事件，才推进本机接受快照和 appliedIds。A2 作者的 confirmPublished 必须发生在此后。共享成功但接受事件失败时，原 outbox 与备份保留，重启完成同一操作，不产生第二个 ID、不删已发布文件。确认后的接受状态能直接提供给 A2 的专用结构修复作者，本轮已有跨模块真实文件检查。

epoch 在确认前变化，返回 held、保留旧接受凭据；已经写共享文件也不能强行应用过期候选。如果 epoch 恰在 accept 的原子安装期间变化，无法撤销已写的事实，返回 `accepted-deferred`：新历史已可靠保存，但当前视图必须重新校验/延后应用，不能显示跳动。原型不操作视图，A4 仍需使用该状态和 epoch 门禁。

只有尚未开始发布的 pending 可以 cancel，且当下规范共享文件必须不存在；取消也保留 intent/blob/备份，不复用旧 intent ID。检测到错误后会话进入 faulted，禁止继续盲写，必须重新打开验证；状态/返回值均隔离副本。

## Node 测试适配的实际保障

安装文件前写入临时文件的完整字节并 fsync；硬链接只暴露完成文件，已存在目标绝不覆盖。子进程可以在只写了一半临时内容时退出，规范文件依然不存在或是完整旧文件。正常完成才移除自己创建的临时文件；中断临时文件保留。

写入排他采用“先安装唯一进程 claim、再枚举其他 live claim”：另一活进程存在则拒绝，两个同时竞争者也可能都保守退让；不删除其他进程的 claim。确认已退出进程的 claim 忽略但保留，PID 复用按活进程处理，宁可要求审阅。六进程竞争检查用另一份独立 exclusive guard 核对无同时进入写区，竞争结束后单进程可再次取得。此结论仅限本地 Node 文件系统，不推定同步目录或移动宿主具有同样语义。

本机 Windows 实测 file fsync 可调用，但 directory fsync 不支持（capabilities.directoryFsync=false）。因此这些检查证明的是**进程中断恢复**；未测试拔电、系统崩溃、磁盘控制器缓存、硬件故障或跨文件系统移动。Obsidian 公共 API 是否能提供所需原子性/持久语义，需要单独适配与验证，不能把 Node 的硬链接协议直接标成 iPad 可用。
