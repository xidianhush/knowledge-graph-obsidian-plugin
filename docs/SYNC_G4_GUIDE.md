# G4：重置、撤销、结构变化与多组竞争

本轮使用新的 **Knowledge Map G4 PC / Knowledge Map G4 iPad** 测试库，不替换旧FB1库或日常库。候选显示0.0.15，正常设置入口仍为 Knowledge Map Sync Candidate。新空坚果云远端：**{{REMOTE}}**，两端同用，不复用旧远端。

## 准备与首次加入

1. 分别解压PC/iPad包，以包内对应库文件夹为库打开；隐藏.obsidian已包含在ZIP中，无需手动访问或替换旧库的插件。
2. 两端信任此合成库内的候选插件，配置自己的Nutstore Sync到上述新空远端。关闭服务自动同步，本轮按步骤手动传输Synthetic/、后续Moved/和Knowledge Map Sync/；不覆盖两端.obsidian或交换凭据。
   - PC与iPad分别重新打开Nutstore Sync设置，核对「远程目录 / Remote directory」均为上述同一路径；本地库名称不同不代表云端目录也应不同。若仍显示按库名生成的路径，先设为本轮远端再同步。首次传输确认列表应包含PC生成的共享JSON上传。
3. 两端打开知识图谱，各只保留一个图谱标签页。先在PC建立共享布局，再让iPad加入同一份：
   - PC：设置 → Community plugins → Knowledge Map Sync Candidate → 图谱布局同步，点「新建共享布局」，在连接选择窗口点「确认」。随后点「审阅并加入」，选「导入本机已有布局」预览卡片，再点窗口底部「确认并加入」。这里的本机已有布局是新G4测试包预置的布局，无需导入JSON文件。
   - 传输：PC在Nutstore Sync手动同步，完成后iPad再手动同步，使PC生成的Knowledge Map Sync目录文件到达iPad。
   - iPad：同一候选设置页点「查找共享布局」（只刷新候选，不自动展开菜单），再点右侧写着「选择已发现的共享布局」的灰色长框，展开选项并选PC那份，再点「选择共享布局」，弹窗点「确认」。随后点「审阅并加入」，选「采用共享布局」预览卡片，再点「确认并加入」。iPad加入PC创建的那份，无需另建一份。若只有占位文字，展开「详细原因」查看，确认PC→iPad传输已完成；点长框仍不展开则导出报告和截图，不强行另建共享布局。
   - 两端设置中的「当前共享布局」编号应相同，图谱应显示相同布局；屏幕大小、缩放与视角可以不同。本步直接确认，无需重复上一轮首次加入测试的取消步骤。
4. 两端导出「G4-起点-PC」「G4-起点-iPad」。报告由正常设置“导出同步状态”生成，按上述名称重命名即可。

## 一：重置与撤销

每次只移动一篇笔记下的一个标题，结束调整模式后，等待设置中无待发布工作/已写入共享目录，再做下一次编辑，避免快速连续操作被自动队列合成同一事务。

1. PC移动 **B.Fourth**，结束编辑，PC同步→iPad同步→检查，两端应采用修改。
2. PC进入调整模式，选中B中的标题后点“重置本组”，结束编辑，导出「G4-重置-PC」。仅B恢复自动布局，A的旧布局应保留。
3. PC依次进行“撤销→重做→重置全部→撤销”，每一步结束编辑、等待保存和共享写入后再继续。撤销重置全部后，应回到重置全部前的布局。导出「G4-撤销重做-PC」。
4. PC再移动B.Fourth，等待保存，PC同步→iPad同步→检查，使两端都具有A/B两个已保存布局。

接收另一端更新后，旧本机撤销记录可能被清空，这是既有防覆盖行为；不要求跨设备撤销对方操作。

## 二：两个独立范围同时竞争

1. 暂不点击坚果云手动同步。PC依次移动A.Second、B.Fourth；iPad也依次移动这两个标题到明显不同的位置。**每次结束编辑且确认没有待发布工作后，再移动另一篇笔记中的标题。**
2. PC同步→iPad同步→PC同步，两端检查；各导出「G4-多域冲突-PC」「G4-多域冲突-iPad」。暂不再拖动。
3. 只在PC点“审阅布局冲突”。若为两个独立范围的两份分支，应看到四个完整组合，每个组合显示A、B的布局。先选择后取消，确认图谱未被取消动作改变；重新审阅，选期望组合并最终确认。
4. PC同步→iPad同步→两端检查，两端应采用同一组合。若选项数不是4、提示存在本机草稿、等待笔记或其它暂停，先导出报告/截图并停下；不要删除历史或反复拖动来制造四个选项。

## 三：文件、目录与标题变化

1. 两端在候选原设置的“包含范围”中保留Synthetic/**，再加一行Moved/**，保存并应用；此时原笔记仍应可见。
2. 只在PC将Synthetic/A.md改名为C.md。PC同步→iPad同步，建图并检查，旧局部布局应跟随C，不应重新导入或变成清空。
3. 只在PC把Synthetic目录改名为Moved。PC同步→iPad同步，建图并检查，应保留两篇笔记的布局。同步服务传输改名可能分为删除/新建，等待两端笔记均到达再判断。
4. PC在Moved/C.md末尾新增一级标题Fifth及一行正文，等待图谱更新；PC同步→iPad同步→检查。新标题可获得空间，原组应保留，必要位移限于该组的适配。再删除刚新增的Fifth与正文，等待更新，重复传输检查。不要删除整个笔记。
5. 两端导出「G4-结构后-PC」「G4-结构后-iPad」，各截一张图谱。

当笔记暂未到达、包含范围/remap不同，或标题身份无法可靠对应时，插件应保留原接受历史并等待，不能同步清空或只保存有效子集。若等待未解除，导出当时报告和说明，不强行继续。

## 四：最终重开与回交

两端完全退出并重开Obsidian，建图、检查，导出「G4-最终-PC」「G4-最终-iPad」。集中回交 **10份JSON**、两端最终图谱/设置截图，以及四选项预览截图。反馈重置/撤销是否符合预期、四组合是否能辨认和点选、取消是否不改变布局、改名/标题变化后的效果。

本轮不测试任意多组合：完整选择组合上限8，超限保留原件并暂停。Windows原生预检是本地复制传输，不能替代本轮iPad/Nutstore。容量、断电/故障恢复、实际旧版回退和发布授权另行处理。
