# G4 当前候选有界测量方案

日期：2026-11-26（Asia/Shanghai）。用户已同意 G4-D1 补测，本轮由 Codex 执行，无需用户操作设备。

## 固定输入与范围

- 复用当前 codex/baseline-convergence 活动工作区，测量在其 .local 下新建独立源码字节副本和合成存储，不再创建 Git worktree。运行前记录 HEAD、源码/驱动摘要及三运行资产摘要；副本重建须匹配当前候选，不能将旧包或归一化差异不明的构建当作相同输入。
- 生产统一宿主、pipeline/layout 模型及实际保存/发布/备份/轮换模块，使用现有 G4 合成辅助器的两篇笔记、两组布局，交替生成独立编辑，沿用历史对照的已加入会话路径。该路径不测一键首次初始化，也不模拟 BasePlugin 原生文件事件。
- App、锁、共享文件和私有存储采用合成内存适配器；不是实际 IndexedDB、磁盘满、Obsidian 完整启动、iPad 或 Nutstore 网络测试。
- 源码和运行逻辑保持原样；只增加私有测量驱动与结果记录，不优化生产代码、不变更容量保护或协议。

## 样本与停止条件

先逐次完成保存及排队发布，再观察状态。最多生成 1024 次独立编辑；初始导入根单列计数，不把它混入编辑次数。409 条已接受操作是旧样本参照，不是目标可用上限或必须达到的数值。

记账校准：本地保存成功不等于共享发布成功。分别记录已保存编辑、已发布编辑、初始根和保留草稿；容量暂停时最后一次保存可能只形成草稿。私有库存使用显式 diagnostics 刷新的计数，state 中缓存值仅作过程观察。准备首轮因此触发的驱动断言失败保留，不列作产品故障或完整计时；源/资产、样本方法、阈值和停止上界不变。

准备阶段在状态不再 ready、存在未完成发布/错误、达到 1024 次编辑或 480 秒准备墙钟上界时停止，记录实际完成编辑数、已接受操作数、共享文件/字节及私有库存/触发项。不得填充副本、删除历史、抬高配额或重试到出现更好看的样本。

整个运行进程上界 1200 秒，由外部看门狗控制；任何未完成阶段保留进度和日志并记未完成，不拼接为全通过。看门狗只结束本次自建测量子进程。

## 三次固定样本测量

三次均从同一持久合成输入开始；每次先关闭宿主，再在同一 Node 进程重新构造宿主。记录该动作范围内的性能时钟，称“宿主冷回放”，不是 OS/进程冷启动。完成后检查已接受历史/布局未变。

1. 冷回放：关闭后 createUnifiedSyncHost 开始至构造/历史读取完成。
2. 完整恢复备份：新空内存目的地，exportRecovery 开始至内部完整核验成功；记录输出文件/字节。该数值不能推导真实文件系统或服务吞吐。
3. 如样本已 paused，通过布局 store 发起编辑至拒绝结束；断言接受快照、已保存布局及共享历史未改。若未遇到暂停，本项记未覆盖，不人为造暂停补通过。

调查线沿用历史值：冷回放 30000 ms、备份 30000 ms、暂停编辑拒绝 5000 ms。它们只用于标出需解释的超时，不是流畅性 SLA。披露三次全部结果及中位数/范围，不删慢样本；若输入因测量变化，停止并报告。

资源只记录 Node memoryUsage 与 OS free-memory 的点状快照；不宣称峰值、iPad 内存、实际私有磁盘量或 OS 可用磁盘。记录 Node/Windows/CPU 方法信息以便解释差异。

## 暂停后的恢复核验

若实际出现容量暂停，完成三次后重开清除会话保存错误，再导出并核验备份。单独计时现有明确预览及确认新逻辑库轮换；记录新根及旧库存保全，确认原布局保持且新根可读。轮换计时不包含之前的备份导出，不绕过授权/完整性门禁。

轮换沿用历史测量的“已接受布局”选项，新根核对该布局；最后已保存但未发布的草稿在旧域/完整备份中保全，不将它自动并入新根或将该明确来源选择写成草稿丢失。

具体暂停原因仅依据完整库存、实际触发项与错误交叉判断；诊断缺失或不一致时明确写未定位，不单凭样本数猜测。

## 交付

原始日志、逐次 JSON、冻结源码清册、资源快照和测量驱动在 .local 私有保留；公开结果只含合成统计、构建/方法和限制。工程检查与本轮测量分别计数，不把旧测试记作新通过。更新 TODO、G4 证据和发布准备清单，并做一次独立方法/结论审查。

超调查线先报告及解释，本轮不自动展开性能重构、iPad 压力测试、真实服务大量文件传输、日常库操作或发布。
