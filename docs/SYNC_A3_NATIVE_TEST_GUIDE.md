# SYNC-A3：iPad 原生存储检查

这次只测 Obsidian 本地存储，不需要安装、登录或运行 Nutstore。使用新建的 **Knowledge Map A3 Native** 独立测试库；原来的 A1 库继续保留。

## 1. 打开独立库

将提供的 `Knowledge Map A3 Native test vault.zip` 传到 iPad，解压。按 A1 时的方式，把里面的 **Knowledge Map A3 Native** 文件夹作为一个新库打开，完整保留其中的 `.obsidian` 隐藏目录。不要只复制 START-HERE 笔记。

如果 Obsidian 询问是否信任仓库作者，由你亲自确认。测试库只包含 **Knowledge Map A3 Native Probe** 探针。首次启用后自动运行并导出报告；也可以在命令面板搜索 **打开原生存储检查** 查看面板。无需安装正式 Knowledge Map。

## 2. 看第一次结果，再完全重开

正常预期是 **通过 17 / 失败 0 / 待重开 1**。“待重开”表示尚未验证重开持久性，第一次出现它是正常的。

先等检查结束，再回到 iPad 的 App 切换器，把 Obsidian 向上划掉，随后重新打开 Obsidian 和这个测试库。探针会自动再次运行。

第二次正常预期是 **通过 18 / 失败 0 / 待重开 0**。其中 `prior private record survives reopening` 检查应能读到第一次留下的合成记录。本轮没有 PC/iPad 写入计数，也不用两端同步文件。

如果出现失败或暂停，保留原结果，直接发报告即可；不需要反复运行、重装或修改存储配置。

## 3. 发回第二次报告

报告自动保存在测试库根目录，文件名为 **SYNC-A3-native-mobile-随机ID.json**。请发送第二次运行生成的报告；有失败也发送同一文件。

报告只有合成检查结果、测试设备标识、Obsidian 版本和源码摘要，不含本机签名密钥、账号或笔记。单次合成数据约 1.28 MB，保留在此库的设备私有存储中；本测试不删除其他库数据。

重开检查通过，只能说明本轮环境下的重开持久性；不等于断电、系统崩溃、iOS 后台运行或正式布局同步通过。
